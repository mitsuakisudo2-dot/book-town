# 余白 — 本を読みたくなるSNS

「読書の終わりを、交流の始まりに。」「本を愛する人を、孤独にしない。」を中心にした、スマートフォン優先の操作できるフロントエンド・プロトタイプです。

## 起動

Node.js 20.19+ または 22.12+ と pnpm を用意し、プロジェクトのディレクトリで実行します。

```sh
pnpm install
pnpm dev
```

本番用の静的ファイルは `pnpm build` で `dist/` に生成されます。

## 試せること

- ホーム → 感想 → 書籍 → 読書家 → 人生の9冊・公開本棚、の往復
- 本・著者・ISBN・読書家・感想の検索、ジャンルによる発見
- 公開／匿名のテキスト投稿、任意の関連書籍、ネタバレ設定
- いいね、コメント、匿名返信、読みたくなった、フォロー
- 読みたい／読書中／読了／積読と、独立した所有の登録
- 人生の9冊の選択・並び替え・コメント（空欄可）
- 名前付き本棚の作成・編集、公開／非公開の切り替え
- 本の手入力登録、ジャンル別の自動分類、状態による絞り込み、ジャンル構成の円グラフ
- 再読み込み後も操作を復元する localStorage 保存

サンプル読書家・投稿は「デモ」と表示します。表紙は既存装丁を再現しないオリジナルの仮デザインです。書籍の紹介文も試作品のために短く書いた文章です。バーコードボタンは、将来の機能説明と現在の手入力へ進むための入口です。

おすすめはデモ用の編集選択です。人気順や読書量・フォロワー数のランキングを用いず、同じ作品への異なる視点、未知のジャンル、静かに愛される作品に出会う入口を用意しています。投稿は有限で、追加表示は明示的なボタン操作です。

## 実装の構造

- `src/types.ts`：書籍、読書家、投稿、返信、読書状態、本棚のモデル
- `src/data.ts`：サンプルデータ
- `src/store.ts`：状態更新と永続化の境界。`repository.load/save` が保存処理を引き受ける
- `src/App.tsx`：画面遷移、ホーム、発見、書籍、投稿、リアクション・返信
- `src/PersonalPages.tsx`：プロフィール、人生の9冊、本棚、マイライブラリ
- `src/ui.tsx`：表紙、アイコン、アバター、フォーカスを保つモーダル
- `src/styles.css`・`src/personal.css`：Tailwind CSSと画面スタイル。キーボード操作・動きを減らす設定に対応

外部書籍API、認証、決済、AI推薦は接続していません。このブラウザ内のデータだけで動作し、他の利用者や端末とは共有しません。保存キーは `yohaku-reading-sns`、データにはスキーマ版を付与しています。

## Supabaseへつなぐとき

永続化アダプターとアクション層を非同期のリポジトリに置き換え、画面にはローディング／エラー状態を追加します。テーブル候補は `books`, `profiles`, `posts`, `comments`, `library_entries`, `shelves`, `shelf_books`, `life_nine`, `follows`, `reactions` です。人生の9冊・本棚の並び順は位置を別列で保存し、読書状態と所有フラグは独立して扱います。

非公開本棚とライブラリには所有者に限定する RLS を設定します。ブラウザ側で隠すだけではアクセス制御になりません。

匿名投稿は内部のアカウントIDを安全管理用に保持しつつ、通常の取得APIには公開用の匿名IDと議論内の固定名だけを返します。サーバー側で議論ごとの別名を発行し、内部IDやフォロー関係から投稿者を推測できないようにします。この試作品の匿名機能は表示を体験するためのもので、サーバーによる匿名性の保証はありません。

ネタバレは本文と返信を明示的な操作まで隠しています。本番では取得APIでもネタバレ本文を分離する設計を検討します。

公開サービスにする前に、通報・ブロック・ミュート、運営による通報審査、スパム対策、削除・復旧、認証、RLS、アカウント管理が必要です。`reports` と `blocks` をアカウントIDに紐づけ、匿名投稿も運営側で追跡できるようにします。匿名の内部IDを一般読者へ返さずに、ブロックしたアカウントの公開／匿名投稿と返信を取得時に除外します。これらの本番機能は今回の範囲には含めていません。
