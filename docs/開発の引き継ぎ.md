## 作るときの規格

けにーさんの決まり（2026-10-16「今後作るときも統一した規格になるように意識して作って」）。同じことを画面ごとに書かず、共通の所にある物を使います。

- **直書きしません。** 色・字の大きさ・角・ボタン・数・言葉・住所・時間を、画面のファイルに数字や文字のまま書かず、下の共通の物を使います。
- **共通の物にない物が要るときは、共通の所に足してから使います。** 画面のファイルの中で同じ物を2度書いたら、共通の所へ移す合図です。
- **新しく共通の物を作ったら、直書きが戻らない確認（tests/ の数の上限か禁止）を一緒に足し、この表に1行書きます。**

## 作業の手順で気をつけること

- **取り込み:** けにーさんへの言葉は平易に（PR は「提案書」、merge は「本体に取り込む」）。取り込みは1本ずつです。了承が要るか、承認なしで取り込める軽微な直し・資料だけの変更かは、運用指針の4章と CLAUDE.md に従います。DB のマイグレーションは、main に入ると自動で本番に適用されます。
- **見直しの重さ:**
  - 小さな直し（画面が変わらない直し、確認の手順の直し、数行の直し）は見直し1回です。
  - DB、ログイン・お金・権限、ホームの大きな画面は、2人で見直します。
  - 迷ったら大きい側にします。
- **自動の確認（CI）を弱める変更はしません。** 必要なら、けにーさんの明示の了承を取ってからにします。
- **GitHub は REST で操作します**（GraphQL は 403 になることがあります）:
  - 提案書を出す: `gh api repos/mitsuakisudo2-dot/book-town/pulls -f title -f head -f base -F draft=true -F body=@file`
  - 下書きを外す: `POST .../pulls/N/ccr/ready_for_review`
  - 取り込む: `PUT .../pulls/N/merge -f merge_method=merge -f sha=<先頭の sha>`
  - CI の結果: `commits/<sha>/check-runs`
  - リポジトリの設定（ルールセットなど）は、この経路では書けません。けにーさんに手順を渡します。
- **本番の確かめ:**
  1. `deployments?sha=` と、その statuses が success になるのを待ちます。
  2. Vercel の接続があれば `get_deployment`（idOrUrl に booktown.page）の `meta.githubCommitSha` が取り込みの sha と同じか見ます。
  3. booktown.page は、作業環境の curl や Chrome からは開けないことがあります。
- **通しの確認（手元）:**
  - ブラウザ: CI と同じ Chrome Headless Shell を使います。CI は `pnpm exec playwright install chromium` で入れるので、版は入っている Playwright が決めます（2026-10-15 は Playwright 1.64、Chrome 156）。作業環境に前から入っているブラウザは古いことがあるので、`BOOK_TOWN_CHROME` で 156 を渡します。
  - デモのビルド: `env -u NEXT_PUBLIC_SUPABASE_URL -u NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY pnpm build`
  - ログインのビルド: `NEXT_PUBLIC_SUPABASE_URL=https://test-project.supabase.co NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_test pnpm build`
  - 立て方: `python3 -m http.server <port> --directory out` で立て、`BOOK_TOWN_URL`・`BOOK_TOWN_CHROME`・`BOOK_TOWN_QA_OUTPUT` を渡して `flock` で1本ずつ流します。ビルドで `out/` が作り直されるので、毎回ビルドしてから流します。
  - 画面の通しの確認は、2026-10-16 から全部が CI で走ります（feedback と poster-journey は demo-journeys に足しました）。手元で流すのは、直した画面の通しと、CI で落ちた通しの原因を探すときです。
  - クラウドの作業環境では、始まりに `.claude/hooks/session-start.sh` が `pnpm install --frozen-lockfile` を済ませ、`BOOK_TOWN_CHROME` に入っている Chromium を渡します（作業環境からは Playwright のブラウザを落とせないため。CI より古い版です）。
- **「戻る」の層（`src/lib/back-layer.ts`）:** 遅いスマホでは、離れた画面の片付け（React の passive effect のあと片付けと `setTimeout(0)`）が数秒待たされ、読書家が「戻る」で戻ってきたあとに走ることがあります。層を外す処理は、外した時から履歴が動いていないとき（`popstate` の数が同じとき）だけ段を消します。層の登録と片付けは `useLayoutEffect` で、画面を離れたその時に行います。確かめは `tests/app-journey.mjs` の「on a slow phone, 戻る from another page returns to the step left」（CPU を6倍遅くして、本屋を開く途中でホームへ出て戻る）。
- **使い心地の見直し:** 画面に関わる変更は、取り込む前に `.claude/skills/booktown-ux-review` の物差しで見直します（スマホの幅で実際に触り、0・戻る・書きかけ・押しやすさなど）。
- **してはいけないこと:**
  - `git add -A` と、むき出しの `git stash`。
  - 作業用の `tests/zz-*` をコミットすること。
  - 新しい依存を足すこと（入れるのは `pnpm install --frozen-lockfile` だけ）。
- **鍵と個人情報:** 鍵はチャットに貼らせません。リポジトリと Actions のログは公開なので、鍵・メール・個人情報を出しません。
- **Supabase の接続（MCP）** は書き込みもできますが、select だけを流します。
- **作業役（Agent）に渡すとき:** 長いコマンドは前面で流すこと、push しないことを書きます。終わったら worktree が片付いているか、サーバーが止まっているかを確かめます。
