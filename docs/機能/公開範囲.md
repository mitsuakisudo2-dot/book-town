# 公開範囲

だれが何を読めるか（表ごとの公開範囲、手で入れた本、ブロック、ログインしていない人、読書記録と見せる範囲）の正本です。ほかの資料はここを指すだけにします。決まりを DB で守る書き方（本を指す物を足すときに広げる関数など）は [DBの変え方.md](../開発と運用/DBの変え方.md) にあります。

- **非公開の棚**: 店主のアプリは全部の棚を `shop_private` にだけ書く。公開する棚は、データベースのトリガーが `shops.public_shelves` に写す。店主は `public_shelves` と `public_scene` を自分では書けない（列ごとの権限）。アプリに不具合があっても、非公開の棚が他の人に届くことはない。
- **店内（Scene）も同じ仕組み。** 店主のアプリは店内の全体を `shop_private.scene` にだけ書き、データベースが公開してよい部分を `shops.public_scene` に写す（関数 `public_scene_of`）。規則は画面の `publicStoreScene` と同じで、置いていないもの、公開でない棚の段、非公開や棚に置いていない本と、その上のPOPを除く。写しの `storeId` はデータベースが本屋のIDに書き換える。
- **手入力の本は、使われている場所で読める。** 手入力やスキャンで登録した本（`source = 'manual'`）を読めるのは、入力した人と、その本を自分で使っている人（読みたいなどの印、マイライブラリ（外していない本）、出会いの記録、投稿とひとりメモ、記録、読書、人生の9冊、ポスターと下書き、自分の本屋の棚と店内。非公開のものも含む）。ほかの人とログインしていない人には、公開の場で使われているあいだだけ見える：開店中の本屋の公開の棚と店内、ひとりメモ以外の投稿（返信、一緒に読むメモ、たたんだ投稿も）、公開の記録、人生の9冊、貼り出したポスター、一緒に読む記録（終わったものも）。運営が隠したものと隠した人のもの、深刻な通報で確認まで見えなくしているものは数えない。ブロックは数えない（ログインしなければ同じものが読めるため）。目録の本（`ndl`）は誰でも読める。
- **ISBN で登録した本の書誌は、非公開の本でも目録になる。** 書誌が取れて判定が済むと、書誌の言葉だけで目録の行になり、誰でも検索で見つけられる（打った題名・持ち主・人数は出さない。けにーさん 10-19「出す」「すぐ」、`private.catalog_promote`）。詳しくは [本と書誌](./本と書誌.md)「図書館の目録」。
  - 決めるのは DB の関数（`private.book_is_listed`・`private.book_is_mine`・`private.book_is_shared`）で、本を指す表や列を足すときの広げ方と速さの決まりは [DBの変え方.md](../開発と運用/DBの変え方.md)「本を指す物を足すとき」にある。
  - （2026-10-18 まで）本のIDを知っている人は、その本に印を付けたり投稿したりでき（外部キーは RLS に関係なく確かめられる）、そうすると題名が読めた。今は、読書家の行がほかの人の本を指す書き込みを DB が断り（`private.own_books_only`、[本と書誌](./本と書誌.md)「自分の本の行」）、写し（`copy_book`）も読める本からしか作れないので、IDを知っているだけでは題名を読めない。表紙の削除依頼（本への通報）は「使っている」に入れない。IDを知らない本の題名を読む手段にしないため。
  - 元に戻すときは、新しいマイグレーションで読み取りの方針を `using (true)` に戻す。行は書き換えていない。ただしこれは、非公開で登録された手入力の本の題名を、誰でも読めるように広げる変更になる。行う前に、だれに何が見えるようになるかを書き出してけにーさんに見せ、明示の承認をもらう（けにーさん 2026-10-22）。
- **店内に並ぶ本の一覧。** `shops.public_scene_books` と `shop_private.scene_books` は、店内に置かれた本のIDをデータベースが自動で並べた列。街の読み込みは、店内を全部読まずにこの一覧で本を集める。
- **他の人の本屋のデータ**は、読み込むときに必ず検証する。棚は `cleanShelves`（`src/lib/town-remote.ts`）で、形が崩れた棚や知らない本を落とす。店内は `sceneFromRow`（`src/lib/walk-remote.ts`）で `validateScene` を通し、崩れたものは書店めぐりに出さない。
- **ブロックは双方向に効く。** どちらからも相手の本屋、投稿、一緒に読む記録が見えなくなり、フォローは両方向とも外れ、新しいフォローや反応、返信もできない。プロフィールだけは見えるままにして、ブロックした人が自分の一覧から解除できるようにしている。誰が誰をブロックしたかは、本人以外には調べられない。
- **ブロックの画面**（管理表43、`src/components/BlockReader.tsx`、`src/lib/blocks.ts`）。相手のプロフィールの「通報」の隣と、便りの「…」から、確かめる小窓（「相手には知らされません」「あとで設定から外せます」）を通してブロックする。ブロックした人のプロフィールには名前と「ブロックを解除」だけを出し、設定の「ブロックした読書家」に一覧と［解除］を出す（いるときだけ）。解除はトーストの「元に戻す」で取り消せる。
  - 街は `TownState.blocked` に相手のIDを持ち、`blocks` の行として足す・外す（`planWrites` の relation）。ブロックした瞬間に、相手の便り・本屋・記録・一緒に読む記録・ポスター・ひとこと、自分の便りへの相手のいいねを街から外す（`withoutReaders`）。自分の返信は外さない（街から消えた自分の便りは、次の保存で削除されるため）。読み込みでも、あとから届く便りでも、データベースに頼らず同じように外す。
  - 解除しても、外したものは次に街を読み込むまで戻らない（トーストでそう伝える）。フォローは戻らない。
  - 見本とデモの街には出さない（通報と同じ）。ログインしていない人には、ログインに招く。
  - **まだ DB で止めていないこと（管理表43の残り）:** ブロックされた側からも、ブロックした人の人生の9冊（`profile_nine`）と、ブロックした人が相手の投稿や POP に付けた反応（`post_reactions`、`pop_reactions`）が見える。ブロックした側の画面では、相手の9冊を出さず、相手の反応は数えない。
- **通報**は運営が Supabase のダッシュボードで読み、状態を変える。アプリストアの審査でも、ブロックと通報は投稿のあるアプリに求められる。
- **返信は1段まで**、ひとりメモには返信できない。どちらもデータベースのトリガーで止める。
- **退会**すると、その人のデータはすべて消える。手入力した本だけは目録に残り、作成者が空になる（公開の場で使われているあいだは読めるが、どこにも使われていなければ、もう誰も読めない）。ただし運営の注釈（`site_notes`）は画面の写しを含むので、退会した読書家の名前や言葉が写っていることがあり、運営が消すまで残る（通報の行と同じく、運営のための例外）。
- **退会した人への通報と、運営の非表示の記録は残る。** 退会した人のプロフィールへの通報（`reports.target_id`）と運営が隠した記録（`moderation_hides.target_id`）は、ほかの人の通報や運営の記録なので、投稿が消えたときと同じく運営のために残す。どちらも、もう何にもつながらない ID だけが残る。

## ログインしていない人の街

- **ログインしていない人も、本物の街を見て歩ける。** 開いている本屋と公開の棚、店内、公開の投稿、プロフィールと人生の9冊、一緒に読んでいる人。読むのはログインなし（anon）で RLS が許すものだけ（`loadPublicTown`、`visitorWalkBackend`）。
- **何かを変えようとしたときに、ログインへ招く。** 本屋を開く、本を並べる、投稿、フォロー、好き、保存、ひとこと。変更は保存の手前で止め（`createTownStore` と `createWalkStore` の `onVisitor`）、「本の街の住人になりませんか」を出す。「フォローしました」などの知らせは出さない。データベースも RLS で断る。
- **自分のページ（プロフィール、自分の本屋、お知らせ、読みたい本）は、ログインの案内になる。**
- **見本。** デモの本屋、読書家、投稿を、本物と並べて出す（`withSamples`）。人がまだ少なくても街が空にならないため。画面には「見本」と出し、保存しない。本物と同じIDがあれば本物を出す。ログインした人の街にも出す（`src/lib/supabase/town-backend.ts`）。
- 書店めぐりの途中位置は、ログインしていないあいだは覚えない。

## 読書記録は、公開するまで自分だけ

- 登録のときの「読み終えた本の記録」は「自分だけ」が先に並び、選ばれている。記録しても誰にも見えない。
- 記録の画面は「自分だけに残します ・ 公開にする」の1行で、押したときだけ公開になる。確認の画面は出さない。公開したときは毎回「公開しました。同じ本を読んだ人に届きます」と出て、その場で「自分だけに戻す」を押せる。本のページとプロフィールの自分の記録には「公開する／自分だけにする」の小さなボタンがある。
- 設定の「読み終えた本の記録」は、下の「見せる範囲」の決まりで変わる（2026-10-16 まではこれからの記録だけを変えた）。

## 見せる範囲（2026-10-16、管理表の8）

- **誰が読めるか（`audience`）と、中身か人数だけか（`detail`）を分けて持つ。** 画面には4つの選択肢として出す。狭い順に「自分だけ」（`private`）、「人数だけ」（`everyone` + `count`）、「フォロワー限定」（`followers`）、「公開」（`everyone` + `content`）。「人数だけ」は読書の状態（読みたい・読書中・読了）だけにある。形と言葉は `src/lib/visibility.ts`。
- **種類ごとに、はじめの範囲を持つ**（`reader_settings` の `records_audience`、`status_audience` と `status_detail`、`shelves_audience`、`stats_audience`、`likes_audience`、`saves_audience`、`encounters_audience`）。はじめは読書の状態が人数だけ、ほかは自分だけ（けにーさん 10-16 05:31Z）。行がなければこのはじめの値。
- 今は読み終えた本の記録だけがほかの人に届くので、設定に並ぶのも記録だけ（`SHOWN_KINDS`、`src/components/VisibilitySettings.tsx`）。ほかの種類は、その画面ができたときに並べる。列とはじめの値は先に入れてある。
- **記録は1件ずつ範囲を持つ**（`reading_entries.audience`）。古いアプリのための `is_public` は残し、データベースが `audience = 'everyone'` と同じに保つ（`private.reading_entry_audience`。古いアプリが `is_public` だけを変えたら、それを範囲に写す）。
- **読める人はデータベースが決める**（`private.may_see`）。本人はいつも読める。ほかの人は、範囲が公開なら誰でも、フォロワー限定ならその人をフォローしている人だけ。どちらでも、ブロックした・された相手と、運営が隠した人のものは読めない。フォローを外すと、その場で読めなくなる。
- **狭めるとすぐ、今までの物も狭まる。** はじめの範囲を狭めると、それより広い今までの記録も、データベースがその場で同じ範囲にする（`private.narrow_past`、1件ずつ別にしたものも狭まる）。画面は「…を自分だけにしました。今までの記録も自分だけです」と伝える。
- **広げるときは一度だけ聞く。** はじめの範囲と同じ記録が1件でもあれば、選択肢の下に「今までの記録も公開にしますか？」と出し、「今までの記録も公開にする／これからの記録だけ／やめる」から選ぶ。答えるまで何も変えない。今までの物を広げるのは、前のはじめの範囲と同じ記録だけで、1件ずつ別の範囲にした記録はそのまま。設定の上に小窓を重ねず、設定の中で聞く。
- **フォロワー限定は、まだ選べない**（`FOLLOWERS_OPEN = false`）。今は誰でもほかの誰でもフォローできるので、選ぶと狭く見えて実は広いため。鍵（管理表の51）が入ったら開ける。データベースはもう守れる。
- 古いアプリの設定（`profiles.reading_visibility`、登録の画面がまだ書く）は、データベースが `records_audience` に写す（`profiles_records_start`、`profiles_records_change`）。'private' にすると今までの記録も狭まる。
- **切り替えの間だけ残ること**（取り込みのあと、古いアプリのタブが開いたままの間）: 新しいアプリは `profiles.reading_visibility` を書かないので、古いタブは古いはじめの範囲を見せる。古いタブは記録を直すとき `is_public` も送るので、新しい画面で狭めた記録を古いタブで直すと、また公開に戻ることがある。どちらも読み込み直せば終わる。
- **51 で開けるときに直すこと**: 古いアプリが `is_public = false` を送っても、フォロワー限定の記録は変わらない（`is_public` がもう false のため）。フォロワー限定を開ける前に、トリガーでこれを自分だけに狭める。
- 確かめは `pnpm test:db` の `tests/db-visibility.test.ts`（移し替え、はじめの値、公開・自分だけ・フォロワー限定、ブロック・隠した人・フォローを外したとき、書ける列、狭める・広げる、古いアプリ、戻す手順）と、`tests/social-journey.mjs` の設定の確かめ。

## 手入力の本を読める人（R2 を広げる）


- `private.book_is_mine` に、マイライブラリの本（外していない行だけ）と出会いの記録（取り消したもの、相手の投稿が消えたものも）を足した。マイライブラリから外すと、ほかの人が手入力した本は、ほかで使っていなければもう読めない。`book_is_listed` は変えていない（マイライブラリは公開されないため）。
