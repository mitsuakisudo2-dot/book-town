# 本棚とライブラリ

マイライブラリ（読書家が持つ本の一覧と状態）、自分で作る棚、棚ごとの見せる範囲の正本です。書店に並べる棚と店内は [書店と書店めぐり.md](./書店と書店めぐり.md)、だれが何を読めるかは [公開範囲.md](./公開範囲.md)、本の行そのものは [本と書誌.md](./本と書誌.md) にあります。docs/09 から移した節です。

## マイライブラリの表（L1、2026-10-14）

設計の全体は共有フォルダの「本の登録と本棚管理_レビューと実装計画_2026-10-13.md」（5-3 と 9-2 の L1）と「いいねと読みたいのメモ_提案レビュー_2026-10-14.md」（2章）にある。表はマイグレーション `20261025000000_library.sql` で足した。アプリは 2026-10-17 から `library_entries` を読み書きし（下の「アプリが読み書きする」）、管理表15 から自分で作る棚（`library_shelves`・`library_shelf_books`）も読み書きする（下の「自分で作る棚」）。出会いの記録は、まだ読まない。

- **4つの表は、どれも本人だけのもの。** ログインしていない人には何も開いていない。ほかの読書家は読めず、書けない。投稿者や店主にも、いいねした人の出会いの記録とメモは見えない（反応そのものは、今までどおり `post_reactions` と `pop_reactions` で受け取った側に届く）。
  - `library_entries`：マイライブラリの本（版ごとに1行）。読書状況（積読・読書中・読了）、読みたい、いいね、所有、どこから入ったか（`source`）、今回追加の回（`batch_id`）、外した印（`removed_at`）、一度でも使った印（`ever_used`）。状態・読みたい・所有を結ぶ制約は置かない。規則はアプリの `src/lib/library.ts` にあり、データベースが断るのは、正しい書き込みなら送らない値だけ（断られると、まだ送っていない変更がまとめて消えるため）。
  - `library_shelves`：読書家が名前を付けるテーマ棚。名前は1〜40字で、重なってもよい（オフラインの2台で同じ「SF」を作っても、片方が断られないように）。並びは英数字のキー（`collate "C"`）。
  - `library_shelf_books`：どのテーマ棚にどの本があるか。複合の外部キーで、自分の棚と自分のマイライブラリの本しか結べない。主キーは読書家・棚・本（`user_id, shelf_id, book_id`）で、新しい行はこの3つを重なりの目印に insert する。棚と本だけのキーだと、外部キーより先に重なりが調べられ、ほかの人の棚の ID を知っている人が、その棚にどの本があるかを1冊ずつ確かめられてしまう。
  - `book_encounters`：この本との出会い。投稿、POP、本のページで押したいいね・私も好き！・読みたいと、本人のメモ（255字まで）。
- **一度でも使った本は、いいねや読みたいを取り消しても残る。** `ever_used` は、自分の本屋に置いたときと、自分の投稿・ポスター（下書きも）・人生の9冊に使ったときに付き、一度付いたら消えない（`false` にする update が来ても、トリガー `library_entries_keep_used` が `true` のまま残す。断りはしない）。外した行にも付く（行は戻さない）。いいねや私も好き！で入った本も、これが付いていれば、本屋から下ろしたり投稿を消したりしたあとでいいねを取り消しても、マイライブラリに残る（N19・N20、2026-10-14）。読みたいや☆を取り消したときも、この印を「何も残っていない」かどうかに数えるので残り、いいねと読みたいのどちらを先に取り消しても同じになる。ただし、外した本をいいねだけが戻した行（`like_restored`）は、いいねが戻す前のこと（外したときに残っていた状態・読みたい・☆・所有・棚と、外していたあいだに付いた状態・所有・使った印。どれも外した本を戻さない）を数えないので、いいねを取り消すとまた外れる。`like_restored` は、そのあと本人が何かを付けたとき（状態・読みたい・☆・所有・テーマ棚・登録、お店や投稿などに使う）に消え、外すだけのとき（読みたい・☆・テーマ棚から外す、状態・所有を未設定に戻す）は消えないので、この行でも、いいねと読みたい・☆のどちらを先に取り消しても同じになる（古いアプリが読みたい・お気に入りの印を外したときも同じ）。いつ使ったかは持たない（並べるのに使わず、人生の9冊には日付がないため）。
- **いいね・読みたい・☆は、どの順で取り消しても同じになる。** 最後のいいねを取り消したとき、行は、どこから入ったかによらず（いいねで入った本も、読みたいや☆で入った本、古いアプリから写した本も）、いいねのほかに何も残っていなければ外れる。読みたい・☆を取り消したときと同じにするため、4-10 の条件1（いいねで入った行）をどの行にも広げた（2026-10-14 に決まった）。いいねで戻した行は、戻す前のことを数えない（上）。わざと登録した本（スキャン、ISBN、手入力、［＋登録］）は、登録の印（`book_marks` の `library`）があるので残る。順で変わるのは、投稿や POP の「読みたくなった」をほかより後に取り消したときだけで、そのときは残る（「読みたくなった」の取り消しは行を見直さない。4-2 の「反応を取り消しても外さない」）。読みたい・☆・古いアプリの読みたいで入った本の両方の順を、共通の例（`sequence`）に置いてある。
- **消さずに印を付ける。** マイライブラリの本と棚には delete の権限がない。外すと `removed_at`、片づけると `deleted_at` が付き、棚の中身と、ほかの棚への所属は残る。消せるのは、棚から本を外したとき（所属の行）と、メモのない出会いを取り消したときだけ。
- **書き方。** 新しい行は全部の列を insert し（重なりは無視）、変えた行は変えた列だけを update する。部分の upsert（キーと変えた列だけ）は、行があっても `source` が空だとして断られるので使わない。所属の表に既定の upsert を送ると、`position` 以外は update できないので権限で断られる。列ごとの権限：
  - `library_entries` の update は、状態、読みたい、いいね、所有、外した印、`like_restored`、`ever_used` だけ。`source`、`added_at`、`batch_id` は最初のまま。
  - `library_shelves` の update は、名前、説明、並び、読みたいの表示、片づけ、見せる範囲（`audience`）、条件（`rule`）だけ。所属の update は並びだけ。
  - `book_encounters` の update は、メモ（`memo`、`memo_at`）と取り消し（`undone_at`）だけ。
  - 規則（`applySet`）が作る行は、どれもこの権限で書ける。共通の例（`apply` と `sequence`）を、アプリと同じ insert と update にして `pnpm test:db` で流して確かめる。
- **時刻。** 端末の時計が進んでいても、未来の時刻は入らない（トリガーが今の時刻に押さえる）。
- **本は消されない。** マイライブラリの本と出会いの本を指す外部キーは `on delete restrict` で、運営が本の行を消そうとすると止まる。
- **設定**（`reader_settings`）：`library_hidden`（隠す既定の棚のキー。英小文字と `_` の1〜32字を20個まで。知らないキーも入り、アプリが無視する）、`likes_in_library`（いいねした本をマイライブラリに入れる。はじめはオン。オフのときは、いいねのほかに何も残していない本を、どこから入ったかによらず、ライブラリ（全部）・まだ振り分けていない・数から隠し、「いいねした本」の棚にだけ出す。隠すのは、いいねを取り消すと外れる本と同じ本で、同じ判定 `heldByLikeAlone` を使う）、`wanted_clears_on_status`（読み始めたら「読みたい」から外す。はじめはオフ。設定を置くことは問い3で決まった）、`memo_hint`（メモの案内を出す。はじめはオン）。古いアプリの upsert は `user_id` と `spoiler_display` しか送らないので、この4つには触れない。

### 出会いの記録（`book_encounters`）

- **1つの押し方に1行。** 同じ投稿への同じ反応、同じ本屋の同じ本の POP への同じ反応、本のページの読みたいは、それぞれ1行（部分一意索引）。POP の置き場所（`placement_key`）は見つけ直すために持つだけで、同じかどうかには使わない（お店のページと書店めぐりで、同じ POP の呼び方が違うため）。行の ID は端末が作る。
- **取り消し。** メモがなければ行を消す。メモがあれば `undone_at` を付けて残し、押し直すと同じ行の `undone_at` を外して使い直す。
- **insert のトリガー**（`private.check_book_encounter`）は、押した本人の権限で動く（security invoker）。投稿と本屋は、その人が読めるものしか見つからない。
  - 見えない投稿と本屋（ひとりメモ、運営が隠したもの、ブロックし合っている相手のもの、閉店中の本屋）は、ないものと同じ誤り（`the post met is not found`・`the shop met is not found`、23503）で断る。外部キーより先に断るので、断られ方からは、その投稿や本屋があるかどうかは分からない。
  - 自分の投稿と自分の本屋への行は断る。
  - 投稿の行は、その投稿自身の本（返信なら返信の本。親の本ではない）だけ。本のない投稿には作れない。POP の行には本屋と置き場所が要る。本のページの行は、投稿も本屋も持たない。
  - 相手（`other_reader_id`）は、端末が何を送っても、トリガーが投稿の書き手か本屋の店主に置き換える。
  - すでに保存した行（同じ ID の本人の行）を送り直したときは確かめず、insert 自身の ID の重なりに任せる。答えが届かずに送り直すまでに、投稿が消えたり、隠されたり、ブロックしたり、本屋が閉まったりしても断らない（断ると、まだ送っていない変更がまとめて消える）。重なりを無視する insert なら何も起きず、ふつうの insert なら重なり（23505）で断られる。見るのは本人の行だけなので、ほかの人の行のことは分からない。消えた投稿への新しい行は、オフラインのあいだに消えたものでも断られる（23503）。
- **相手が消えたとき。** 投稿が消えると `post_id` が空になり、行とメモと相手は残る。本屋が消えると `shop_id` が空になる。相手が退会すると `other_reader_id` が空になる。本人が退会すると、行ごと消える。
- 今あるいいね（`post_reactions`・`pop_reactions`）は写さない。出会いの記録は空から始まる。
- **ほかの人の店で（`via = 'shop'`、管理表9、2026-10-25、マイグレーション `*_encounters_and_history.sql`）。** POP のない本を、ほかの人の本屋で手に取って読みたいにしたとき。本屋だけを持ち（置き場所は持たない）、相手は店主。種類は読みたいだけで、本屋と本ごとに1行。閉店中の本屋・見えない本屋・自分の本屋の断り方は POP と同じ。
- **出会いは本人の日記（管理表9、2026-10-25 Claude の仮決め）。** 表は「どこで・誰から出会ったか」とメモを持つだけで、押した反応そのもの（相手に届くいいね）、読みたい本、ライブラリの決まりは表を見ない。ライブラリの「いいねした本」と「いいねだけで入った本」は今までどおり街の反応から決める（`townEncounters`）。だから本人が出会いを消しても、反応・読みたい・ライブラリは変わらず、表に書けなかったとき（古いタブ、届かなかった保存）も、ライブラリは食い違わない。
- **登録の前の出会い。** 出会いの行は、読書家の行の決まりどおり自分の本（ほかの人が手で入れた本なら写し）を指す。あとで同じ ISBN を登録すると同じ本になり、出会いはそのまま引き継がれる。

### 操作の履歴（`library_events`、管理表9、2026-10-25）

マイグレーション `*_encounters_and_history.sql`、テスト `tests/db-encounters-history.test.ts`。

- **何を残すか。** マイライブラリの行（`library_entries`）と棚の本（`library_shelf_books`）が書かれるたびに、データベースが変わったことを1つずつ残す。入れた（`added`、`became` はどこから入ったか）、外した・戻した、状態（`was` と `became`）、読みたいを付けた・外した、持っているか、自分の棚に入れた・外した（`shelf_id`）。アプリは書かない（どの画面・古いタブ・古いアプリの印の写しからでも同じに残る）。いいね・私も好き！は出会いの記録にあり、ここには入れない。店の中の置き場所の移動は、置く仕組み（管理表25）の新しい形で足す。
- **見ただけでは残さない。** 開いた、見た、探したは何も書かない。
- **本人だけ。** 読めるのは本人だけで、本人も書き換え・削除はできない。ログインしていない人とほかの人には何も見えない。
- **残すのは本人の操作だけ。** データベースの仕事（マイグレーション、夜の処理、写しへの付け替え）と退会の途中は何も残さない（`private.asked_by_reader`）。読書管理モード（98）でした操作は `manage` が付き、街の数（105）から外せる。
- **1年で消す。** 毎晩 19:31 UTC（日本の 04:31）に1年より前の行を消す（pg_cron `library-events`、`private.forget_library_events`）。
- **書き込みを止めない。** 1人が1日（UTC）に50000行を超えたら、その日の残りは残さないだけで、ライブラリの書き込みは通す（数えるのは `private.library_event_days`、だれも読めない）。シリーズ200巻を登録して整理しても1000行ほど。
- **本ではなくライブラリの行を指す。** 外部キーは `library_entries (user_id, book_id)` で、`books` を指さない。`books` を指すと、目録の行を取り出すとき（`private.catalog_used`）とスキャンで取り消した本を消すとき（AUD-055 の `private.book_used_besides_own`）に「使われている本」と数えられ、取り消した本が消えなくなるため。ライブラリの行が消えると（取り消した本を消す、退会）、履歴も一緒に消える。あとで行を自分の写しへ移すマイグレーションを書くときは、履歴を先に移す（`give_own_copy` は行を作り直すため）。
- **戻すとき。** マイグレーションの頭の「Rollback」。データは移していないので、表と関数を外すだけ（`tests/db-encounters-history.test.ts` が流して、前と同じに戻ることと、もう一度足せることを確かめる）。

### 古いアプリの印を写すトリガー（`book_marks_follow`）

- マイライブラリを知らないアプリ（開いたままの古いタブ、巻き戻したアプリ）が `book_marks` に書いた印は、データベースがその人のマイライブラリの行に写す（`private.library_follows_marks`）。写し方はアプリの `followMarks`（`src/lib/library.ts`）と同じで、どちらも同じ例（`tests/fixtures/library-cases.json`）で確かめる（`pnpm test:library` と `pnpm test:db`）。
  - 印を付けたとき：行がなければ作る（`source = 'legacy'`、時刻は印の時刻）。読みたい・お気に入り・登録の印は、外した行を戻す（レビュー 4-2 の「戻す規則」）。読みたいは `wanted_at` を付け、読了は状態を読了にする。印は本人の操作なので、いいねで戻しただけの印（`like_restored`）は消える。
  - 印を外したとき：読みたいは `wanted_at` を外し、読了は「読書中」にする（古いアプリが読了を外すのは、読み直しを始めたときだけ）。読了を外したときは、アプリで読み始めたときと同じく `like_restored` も消す。ほかの印を外しても `like_restored` は変えない（アプリで読みたい・☆を外したときと同じ）。読みたい・お気に入り・登録の印を外して何も残っていない行だけを、マイライブラリから外す（読みたい・お気に入りの印を外したときも外すのは、レビュー 4-2 の最後の行。2026-10-14 にけにーが決めた）。残すものは、状態、読みたい、所有、いいね、一度でも使った印（`ever_used`）、片づけていないテーマ棚、登録とお気に入りの印、自分の読書記録、メモのある出会い（取り消したものも）。お店の棚、投稿、ポスター、人生の9冊そのものは見ない。
- **1回の保存の順。** 古いアプリは1回の保存で、外した印をすべて消してから、足した印を書く（`src/lib/town-remote.ts` の `planWrites`）。トリガーは1つずつ写すので、読みたいを外して読了にした保存では、ほかに何も残らない行はいったん外れ、読了は外した行を戻さないので、読了のまま外れる。`markChanges` も同じ順に並べ、共通の例（`save`）を `pnpm test:library` と、`planWrites` の順で流す `pnpm test:db` で確かめる。
- **ヘッダーの約束。** 新しいアプリは、すべての通信にヘッダー `x-booktown-library: 1` を付け、マイライブラリの行を自分で書く。このヘッダーのある書き込みでは、トリガーは何もしない（行の `updated_at` も変わらない）。ほかの値とヘッダーなしは、古いアプリとして写す。ヘッダーを偽っても、変わるのは自分の行の写しだけ。印は重なりを無視して upsert されるので、すでにある印ではトリガーは動かない。
- **security definer にしてある。** アカウントの削除は `auth.users` からの連鎖で `book_marks` に届き、そのあとのトリガーは削除した役（supabase_auth_admin）で動く。この役はマイライブラリの表に権限がないので、呼んだ人の権限で動かすと削除ごと失敗する。トリガーが触るのは、その印の持ち主の行だけで、退会の途中（プロフィールがもうない）では何もしない。`pnpm test:db` の「deleting an account removes everything it owned」は、superuser でない supabase_auth_admin で削除して確かめる。

### いまあるデータからの埋め戻し

- マイグレーションを流したときに一度だけ、それまでにしたことからマイライブラリを作る（`private.library_backfill`。もう一度流しても、そのあと何もしていなければ何も変わらない）。どの行も `source = 'legacy'` で、所有は付けない。状態が付くのは、読了の印（読了）と、終わっていない読書（読書中）だけ。新しい状態は作らない。
  - 先の手順が作らなかった本を、次の手順が足す。順は、印（登録・読みたい・お気に入り・読了。読みたいは `wanted_at` も）、自分の読了の記録、終わっていない読書、終わった読書、自分で使った本（投稿、ポスターと下書き、人生の9冊、自分の本屋の棚（非公開の棚も）と店内）。最後の手順は、その中で一番早い時刻を `added_at` にする。自分で使った本の行には、どの手順で作った行でも `ever_used` を付ける。人生の9冊はプロフィールの、本屋の棚と店内は本屋の作られた時刻で代える。本でない ID（見本の本など）は飛ばす。
  - いいねは写さない。本屋の表（`shops`、`shop_private`、POP の反応）と本は書き換えない。
  - L2b までは、どのアプリもマイライブラリの操作を送らないので、そのあいだに本屋に置いたり投稿・ポスター・人生の9冊に使ったりした本には、行も `ever_used` も付かない。L2b のマイグレーションで `private.library_backfill` をもう一度流して追いつく。2回目は足すだけで、行のない本に行を作り、状態のない行のうち読書が続いているものを読書中にし、`ever_used` のない行に付ける。外したり戻したりはしない（`pnpm test:db` が、あとからの投稿を2回目で拾うことを確かめる）。
  - 2回目は流さないことにした（2026-10-17）。アプリが、行のない本の行を毎回その場で作り、使った本の行は使うのをやめるときに書く（下の「アプリが読み書きする」）ので、データベースに行がなくても画面は同じになる。

### 手入力の本を読める人（R2 を広げる）

### アプリが読み書きする（L2、2026-10-17）

- **アプリは自分で行を書く。** すべての通信に `x-booktown-library: 1` を付ける（`src/lib/supabase/client.ts`）ので、古いアプリの印を写すトリガーはこのアプリの書き込みでは動かない。印（`book_marks`）はこれまでどおり書き、ほかの画面とほかの読書家の見え方は変わらない。
- **行は、読書家が変えた本だけ持つ。** 持っている行は `TownState.libraryEntries`（ログインした人は `library_entries`、デモは localStorage の同じ保存）。それ以外の本は、印・自分の記録・読書・自分の投稿・ポスター・人生の9冊・自分の本屋から、埋め戻しが作る行と同じ形を毎回その場で作る（`entriesOf`、`src/lib/library-town.ts`）。だから、埋め戻しのあとに使った本も、ライブラリより前のデモも、行を書かずにライブラリに入っている。作った行の時刻は `LEGACY_AT`（2026-10-01）からの並びで、本当の時刻ではない。
- **いいねは、出会いの記録ができるまで（管理表 9・10）街の反応で代える。** 投稿のいいね・読みたくなった、POP のいいね・私も好き！・読みたくなった（自分の投稿と自分の本屋は除く）を出会いとして読む（`townEncounters`）。いいねだけの本は、いいねがあるあいだライブラリに入る。設定（`likes_in_library` など）はまだ読まず、はじめの値で動く。
- **読みたい・読了の一覧は、操作した本だけ行に合わせる。** 読みたい・☆・登録・読書を始める・終える・記録は、どれも `applyOp`（`src/lib/library.ts`）を通り、操作した本だけを `wishlist` と `finishedBooks` の最後に足すか外す（`relisted`）。ほかの本は順も印もそのままなので、保存が途中で切れて印と行が食い違っても、次の操作がほかの本の印を消さない。読書を始めると読書中になり、読了の印は外れるが読みたいは外れない（問い7）。登録を外すと、ほかに何も残っていない本だけライブラリから外れる（`withoutRegistering`。古いアプリが登録の印を外したときと同じ）。
- **一度使った本の行は、使うのをやめるときに持つ。** 作った行の「使った印」は、投稿・ポスター・人生の9冊・本屋の棚がそこにあるあいだしか分からない。だから、使うのをやめる操作（投稿を消す、9冊を変える、棚から下ろすなど）で、使った印のある行をまだ持っていない本は、行を持って印を付ける（`keepingUses`、`src/lib/store.ts` の `commit`）。ほかの操作（フォロー、いいねなど）では行を書かないので、ライブラリの書き込みがほかの操作を止めることはない。ほかの端末で使うのをやめたときは、この端末では行を持たない（その端末が持つ）。
- **書くのは変えた列だけ。** 部分の upsert はしない（設計どおり）。新しい行は全部の列を重なりを無視して insert し（`onConflict: user_id,book_id`、`ignoreDuplicates`）、入らなかった行（ほかの端末がもう作っていた）には、変えた列だけを update で送る。前からある行も変えた列だけを update する（`planWrites` の `library-entries`、`src/lib/town-remote.ts`）。行は本のすぐあと、印より先に書くので、保存が途中で切れても、行が印より遅れることはない。見本の本は `sampleBookRowId` で書き、目録の行を先に書く。
- **積読は持っている本。** 積読にすると、所有は「持っている」になる（どの画面から付けても同じ。`applySet`、`src/lib/library.ts`）。「持ってない」と書いた本も「持っている」に変わる。けにーさんが 2026-10-18 に決め、10-14 の問い5「積読にしても所有は書かない」を変えた。逆に、積読の本を「持ってない」にしても積読は外れず、両方が付いたままになる（けにーさん 2026-10-18 のカード「両方残す」。資料4章の「所持なし＋積読の矛盾は防止」はこれで変わった）。連続設定でも、積読を選んで「持っている」を切れば両方が付く。
- **まとめて変えて、戻す。** 画面は `changeLibrary(本, 変えること)` で状態・読みたい・所有・☆・外すを変え、戻すための控え（`LibraryUndo`）を受け取る。`undoLibrary` は、そのあと変わっていない本だけを前に戻し、何もない所から入れた本は、何も付いていない外した行にする（行は消さない）。
- **まだしていないこと。** 出会いの記録とメモ（9・10）、設定（8 の残り）。デモで古いタブが保存すると、そのタブの知らない行は消える（デモだけ）。
- **確かめ:** `pnpm test:library`（`tests/library-town.test.ts`：作る行、持つ行、読みたい・読了の読み戻し、外す、戻す、デモの保存、行の読み込み、書く列）と `pnpm test:supabase`（「the app's library is written by the app, and comes back as the reader left it」）。

### 自分で作る棚（管理表15、2026-10-17）

- **棚は3つの仲間。** 決まった棚（読了・積読・読書中・読みたい本・いいねした本・お気に入り。行から毎回計算する `DEFAULT_SHELVES`）、自分で作る棚（`library_shelves`、画面では「棚」）、スマート本棚（条件で自動で集まる棚。下の「棚ごとの見せる範囲とスマート本棚」）。1冊の本は自分で作る棚にいくつでも入り、読書の状態や決まった棚はそのまま残る。書店の陳列棚（`Shop.shelves`）とは別のもので、棚に入れても店には並ばない。
- **画面。** ライブラリの棚の並びで、決まった棚のあとに自分で作った棚（作った順。`position` は時刻の62進で、ほかの端末で作った棚も作った順に並ぶ。`positionAfter`）と［棚を作る］が並ぶ。空の棚は数を出さず、「ライブラリから選ぶ」でライブラリ全体から選んで入れる。［選ぶ］の帯の「自分の棚」の段で、選んだ本を棚に入れる・外す（全部入っていれば光り、押すと外す）。本のカードには、今開いている棚のほかに入っている棚を「SF・文学 ほか1」と出す。棚の名前（40字）・どんな棚か（500字）・「読みたい」だけの本も並べるかは［棚を編集］で変え、［この棚を消す］は片づけ（`deleted_at`、本はライブラリに残る）で、知らせの［元に戻す］で戻せる。
- **書きかけ。** 棚の名前と説明は `src/lib/library-shelf-draft.ts`（`owner/new`、`owner/<棚の ID>`）に残し、街に保存できたら離す（`useKeptUntilSaved`）。
- **書き方。** 新しい棚は全部の列を重なりを無視して insert し、前からある棚は変えた列だけを update する（`planWrites` の `library-shelves`）。棚の本は、外したものを delete、入れたものを重なりを無視して insert する（`shelf-books`）。書く順は、本の行（`library-entries`）→ 棚 → 棚の本。棚の本には本の行が要る（外部キー）ので、行を毎回計算していた本を棚に入れると、その行も持つ（`withLibraryOp`）。見本の本は `sampleBookRowId` で書く。
- **戻す。** 棚に入れる・外す操作の控え（`LibraryUndo.shelves`）は、その操作が触った棚の所属だけを、入れた時刻と並びごと元に戻す。ほかの棚の所属は変えない。
- **確かめ:** `pnpm test:library`（`tests/library-town.test.ts` の「a shelf is made last…」から4つ）と `pnpm test:app`（「a shelf of the reader's own is made, filled from the library, kept, and put away with undo」）。

### 棚ごとの見せる範囲とスマート本棚（管理表15 の2本目、2026-10-17）

マイグレーション `20261103000000_shelf_audience.sql`。

- **見せる範囲は棚ごと。** 自分で作る棚は `library_shelves.audience`、決まった棚は `reader_settings.shelf_audiences`（キーは `DEFAULT_SHELVES` のキー、値は範囲。書いていない棚は棚のはじめの値 `shelves_audience` に従う）。選べるのは記録と同じ「自分だけ」と「公開」（フォロワー限定は51のあと、`choicesFor("shelves")`）。新しい棚ははじめの値から始まる。
- **まだ誰にも見せない。** 公開にした棚をほかの読書家に見せる場所は、けにーさんの判断で「まだ見せない」（2026-10-17 04:47Z）。範囲は選んで保存するだけで、RLS は本人だけのまま、`book_is_listed` と `book_is_shared` も広げていない（広げると、手で入れた本の題名が理由なく読めるようになる）。画面は「今はまだ、ほかの読書家に本棚を見せる場所はありません」と言う。見せる場所を作るときは、そのページのための関数で `private.may_see` を使って読ませ、その2つを一緒に広げる。
- **はじめの値を狭めると、棚も狭まる。** データベースのトリガー `reader_settings_narrow_shelves` が、はじめの値より広い棚と `shelf_audiences` の値を、その場で狭める（記録の `narrow_past` と同じ）。アプリも同じことをする（`withVisibility`）。広げても棚は広げない（アプリは「今までの分も」と答えたときだけ、前のはじめの値と同じ棚を広げる）。棚のはじめの値は、まだ設定の画面に出していない。
- **スマート本棚は、条件だけを持つ。** ［棚を作る］で「自分で入れる／条件で集める」を選ぶ（けにーさん 05:39Z）。条件は `library_shelves.rule`（JSON、4KBまで。`SmartRule`）に、読書の状態・持っているか・出会った場所・ライブラリに加えた時期・著者・ほかの棚を持つ。条件どうしは「すべてに合う」、同じ条件の中は「どれか1つに合う」。どの本が並ぶかは端末がライブラリの決まり（`filterLibrary`）で毎回計算し、`library_shelf_books` に行を持たない。著者は検索と同じたたみ方（`searchFold`）で名前の一部でも合う。「ほかの棚」には自分で入れる棚だけを選べ（スマート本棚の入れ子はない）、スマート本棚には手で本を入れられない（［選ぶ］の帯にも出さない）。作った棚の種類は変えられない。条件の中身はアプリが確かめ（`readRule`）、この版のアプリが読めない条件の棚は画面に出さず、そのまま残す。出会った場所は `ENTRY_SOURCES` を「自分で登録・検索・書店めぐり・便り・読みたい・自分の書店・そのほか」にまとめて出す（`MET_PLACES`）。
- **古いデータベースでも書ける。** アプリとマイグレーションは別々に本番に届くので、自分だけで条件のない新しい棚は `audience` と `rule` を送らない（データベースの既定値と同じ）。読むときは列がなければ「自分だけ・条件なし」として読む。
- **書きかけ。** スマート本棚の条件も、名前と説明と一緒に `library-shelf-draft.ts` に残す。
- **確かめ:** `pnpm test:db` の `tests/db-shelf-audience.test.ts`（前からの棚、公開の棚とスマート本棚を作る、ほかの人とログインしていない人は読めない、断る値、狭める、戻す手順）、`pnpm test:library`（「a smart shelf gathers…」から3つと `tests/library.test.ts` の条件の確かめ）、`pnpm test:app`（「a smart shelf gathers by its conditions, and each shelf says who may see it」）。
