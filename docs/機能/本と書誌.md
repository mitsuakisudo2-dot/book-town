## 作品と版（2026-10-16、管理表の4）

3つを分けて持つ（けにーさん、10-16 13:07Z）。**作品**（`works`、本文そのもの）、**版**（`editions`、ISBN 1つ。文庫と単行本は同じ作品の別の版）、**登録**（`books` の1行、だれかが登録した1冊）。ISBN のない手入力の本は、その登録だけで1つの版。版は自分の ID（`editions.id`）で持ち、ISBN は版の属性の1つ（けにーさんの書誌マスタの見直し ⑤、10-16 22:36Z。マイグレーション `20261031000000_edition_ids.sql`、下の「版の ID」）。感想・投稿・POP・ポスターは作品で集まり、自分の記録・印・棚は自分の登録のまま（アプリが作品を読むのは次の提案書から）。1作品＝1巻。シリーズと巻（管理表6）は作品の上に足すので、上巻と下巻は別の作品（下の「シリーズと巻」）。マイグレーション `20261027000000_works.sql`。

- **まとめ方。**
  - 同じ ISBN は、原則として同じ版。ISBN のある本は、登録したその場でその版に入り、版の作品につながる。ISBN-10 はアプリが ISBN-13 に直して保存し、DB も13桁しか受け取らないので、同じ本は同じ番号になる。
  - 登録のときに題名や著者は比べない。運営の確認や照らし合わせで登録が止まることはなく、ほかの人の登録（非公開のものも）は、登録の結果にもエラーにも影響しない。ほかの人がその ISBN を登録しているかどうかは、登録の様子からは分からない。
  - 待つのは、同じ ISBN の別の登録が保存の途中にあるときだけ（同じ ISBN の初めての登録が同時に来ても1つの版になるように）。登録は保存されるまで版の行を押さえる。版があればその行を止め、なければ自分で作った行なので、あとから来た同じ ISBN の登録は、版があってもなくても同じように待つ（新しい ISBN のときだけ待たせると、待ち時間で分かってしまう）。押さえるのは行なので、何千冊をまとめて送られても DB 全体の鍵の表は埋まらず、止まるのはその ISBN の登録だけ。残る違いは、初めての ISBN では作品と版の2行を書く分だけ処理が数十マイクロ秒長いことで、ネットワークの揺れよりずっと小さい。`tests/db-works.test.ts` が、隠れた本があってもなくても、登録した人に分かることと押さえる行が同じで、300冊送っても鍵の数が増えないことを確かめている。
  - 本の ISBN を直すと（本人でも運営でも）、その本は新しい ISBN の版へ移る。ISBN を消すと、その本だけの作品になる。移ったことは履歴に残る。題名を直しても作品は変わらない。
  - 版どうし（ISBN が違う本や ISBN のない本）を1つの作品にするのは、運営がまとめたときだけ。まとめた結果は版ごと残るので、あとからそのどれかの ISBN で登録された本も、そのまま同じ作品に入る。
  - 方針は「誤ってまとめるくらいなら、まとめずに候補に残す」（10-16 12:10Z）。
- **次の工事（書誌マスタ）。** 版の書誌（書名・著者・出版社）を、国立国会図書館と openBD の公開データから裏側で入れ、登録の題名との食い違いを確かめる。比べる相手はこの公開の書誌だけで、ほかの人の登録とは比べない。食い違っても登録は止めず、直すのは裏側。仕様はけにーさんの見直し（10-16 22:36Z）を入れて決まっている（共有の資料「書誌マスタ　仕様」）。取りに行くのは Supabase の中（pg_cron と pg_net）で、Actions のログに ISBN を出さない。取ってくる所までは下の「書誌マスタ」。
  - そのときに気をつけること: `editions` には、非公開で登録された本の ISBN と、最初の登録の日時（`created_at`）も入っている。読めるようにするときは誰でも見られる本の版だけにし、`created_at` は出さない。送り直しや ISBN の直しで、本が1冊もない版と作品も残るので、取りに行く前に本のある版だけに絞る。
- **今ある本。** 移す工事で、ISBN ごとに版と作品を1つずつ（いちばん古い本の日付で）、ISBN のない本には1冊ずつ作品を作る。本の列（題名・ISBN・作成者・日時など）は1つも変えない。本番は17冊（ISBN のある本が12冊、すべて違う ISBN）なので、12の版と17の作品になる。
- **見せる範囲。**
  - `works` と `editions` は API から誰も読めない。版の書誌は `private.edition_sources` に入り、読めるのは `book_bibliography` を通した分だけ（下の「書誌マスタ」）。
  - `books.work_id` は本と一緒に読める。作品の ID は新しいでたらめな ID で、本の ID を使わない。同じ作品のほかの本は、その本が読める所でしか読めない（`hide_registered_titles`）。作品は ISBN だけで決まるので、作品の ID から、ほかの人が非公開で登録したかどうかは分からない。ただし運営がまとめた版の ISBN をあとで登録すると、その本はまとめた作品に入るので、その版がまとめられたこと（だれかが登録したこと）は分かる。運営は候補（誰でも読める本）からまとめ、非公開の本の ID ではまとめない。
  - 読書家は作品を書けない。`books` の列の権限から `work_id` を外していて、書こうとすると断られる（アプリは書かない）。作品は DB のトリガー（`books_work`、`books_work_edited`）が決め、挿入で名指しされた作品も使わない。同じ本を送り直しても、新しい作品はできない。
  - 本の版（`books.edition_id`）は、`work_id` と同じく読書家は書けず、`work_id` と違って API からも読めない（アプリは読まない）。
- **アプリが読む作品。** アプリは本と一緒に `work_id` を読み（`src/lib/supabase/town-backend.ts` の `BOOK_COLUMNS`）、`Book.workId` に入れる（`bookFromRow`）。`workOf`（`src/lib/works.ts`）はこれで同じ作品を見分け、ライブラリの数（同じ作品の版は1つと数える）と、ひとことで読みかけの本の行を伏せる判定（`guardedWorks`。ほかの人が同じ ISBN を別に登録した本のひとことも伏せる）に使う。デモの本と見本は作品を持たず、それぞれが自分の作品になる。登録したばかりの本は、次に街を読むまで作品を知らない（アプリは書くときに作品を受け取らない）が、同じ ISBN の本はライブラリの数でもともと1つに数えるので、数は変わらない。列を読み忘れると型の確かめ（`pnpm typecheck`）が止める。
- **運営の道具**（Supabase のダッシュボードの SQL Editor で流す）。本の ID は、手入力の本では題名を隠す鍵なので、公開のリポジトリや Actions のログに書かない。そのため、この操作はマイグレーションにしない。ISBN のある本を渡すと、その版（同じ ISBN の登録すべて）ごと動く。どの道具も、終わるまで本の書き込みを待たせるので、途中に登録された本も、終わったあとの作品に入る。
  - 候補を見る: `select * from private.work_candidates();` 誰でも読める本（目録の行と、公開の場で使われている手入力の本）の題名と著者だけで作る。非公開の登録は使わない。題名は検索と同じたたみ方（`src/lib/search/fold.ts` の `searchFold` と同じ手順。旧字、かなとカタカナ、長音もそろう）で、同じか、一方がもう一方の頭で数字が同じとき（「華氏451度」と「華氏451度 新訳版」は候補、「ONE PIECE 1」と「10」、「進撃の巨人」と「進撃の巨人 1」は出さない）。著者は、同じ人がいるか、一方がもう一方に含まれるとき（「ブラッドベリ, レイ」と「レイ・ブラッドベリ 著」は合う。「村上春樹」と「村上龍」、「スティーヴン・キング」と「ホーキング」は合わない）。著者が空の本は出さない。同じ題名と著者の作品がたくさんあるときは、いちばん影響の大きい作品と1組ずつ。公開の記録をつけた人の数・公開の感想の数・並べている開店中の本屋の数を返し、合計の大きいものから並ぶ。数えるのは誰でも見られるものだけで、ライブラリ、非公開の記録、隠れた投稿は数えない。
  - まとめる: `select * from private.join_works('<残す作品の本>', '<移す作品の本>');` まとめの ID と、移った本の数を返す。移した側の作品は消さず、`merged_into` に行き先を残す。動いた本の `updated_at` は変えない（本の中身を変えたのではないので、`books_touch` は作品だけが変わる更新では動かない。ISBN を直したときは変わる）。
  - まとめを戻す: `select private.undo_join('<まとめの ID>');` そのまとめで移った版（ISBN のない本の版も）と、そのあとその版に登録された本を元の作品に戻し、行き先もまとめる前のとおりにして、2つの作品に「別の作品」の印を付ける。あとのまとめで残した側がさらにまとめられているときは、先にそちらを戻す。まとめの ID は `select * from private.work_joins order by joined_at desc;`。
  - 外す: `select private.part_books(array['<本>']::uuid[]);` 1つの作品の中の版（渡した本の版ごと。ISBN のない本はその本の版）を新しい作品に移し、元の作品とのあいだに「別の作品」の印を付ける（候補に戻ってこない）。違う作品の本を混ぜたときと、作品の本を全部渡したときは断る。戻すときは `join_works`。
  - 別の作品の印: `select private.keep_apart('<本>', '<本>');` 2つの作品を候補から外す。印は付けたときの作品に残り、まとめられた作品はまとめた先の作品として読む（`merged_into`）ので、まとめても戻しても印を書き換えずに正しい作品を指す。印をやめるときは、たどった先が2つの作品になる行を消す: `delete from private.works_apart x using public.works a, public.works b where a.id = x.work_a and b.id = x.work_b and array[coalesce(a.merged_into, a.id), coalesce(b.merged_into, b.id)] <@ array['<作品>', '<作品>']::uuid[];`
  - 履歴: `private.work_joins` にまとめ（動かした版と ISBN、戻したか）、`private.work_changes` に本ごとの移動（ISBN を直した `edited`、まとめた `join`、戻した `unjoin`、外した `part`）が、元と先の作品と時刻つきで全部残る。登録で版に入ったことは、ISBN が決めたことなので残さない。
- **移す工事の確かめ**（ファイルの中、1つのトランザクション）。
  - 本を指す表を先に、本を最後に止める（逆だと、本を指す表に書いている人と待ち合って止まることがある）。`supabase db push` はファイルを BEGIN なしで送り、裸の `lock table` はそこで断られるので、`do` の中で止める（`tests/db-copies.test.ts` がどのマイグレーションにも裸の `lock` がないことを確かめる）。
  - 本と、本の ID を持つ9つの表（投稿、印、マイライブラリ、テーマ棚、出会い、記録、読書、人生の9冊、ポスター）の控えを `keep` に取る（控えの名前 `20261027000000_works`）。
  - `check_copy` で行とつながりを確かめ、そのうえで、本の列が控えと同じか、同じ ISBN の本だけが同じ作品にいるか、本が版の作品にいるか、どの作品にも本があるかを確かめる。1つでも違えば全部取り消し、本番は元のまま。「どの作品にも本がある」は工事のときだけの確かめで、そのあとはまとめた側の作品などが空で残る。
  - 本番で確かめ（本17冊がどれも版の作品にいる）、控えは `20261030000000_drop_kept_copies.sql` で消した。
- **戻すとき。**
  - アプリが `work_id` を読む前なら、マイグレーションの頭に書いた SQL（トリガー・関数・表と `work_id`、版へのつながりを外し、`books` の書く権限を元に戻す）を新しいマイグレーションで流す。本の行は無傷。`pnpm test:db` が、戻したあと DB が工事の前と同じになり、控えを消せばもう一度流せることを確かめている。
  - アプリが `work_id` を読むようになったあとは、先にアプリを前の版に戻してから。DB にない列を読むと街が開かない。
  - 控えは消したので、本の値を控えから戻すことはもうできない（工事は本の列を1つも変えていない）。
- **テスト**（`tests/db-works.test.ts`）: 読書家のいる DB での移す工事（どの表の行も変わらない、版と作品の分かれ方、控え、見える本が前と同じ）、隠れた本があってもなくても登録した人に分かることと押さえる行が同じで、たくさん送っても鍵が増えないこと、新しい本（同じ ISBN、新しい ISBN、ISBN なし、送り直し、同時に2冊、名指しの作品は使わない）、ISBN を直すと版を移ること、読書家が作品を書けないこと、API から作品・版・道具に届かないこと、たたみ方が検索と同じこと、候補の規則と順（非公開の本も、ライブラリや非公開の記録、運営が隠した投稿も使わない、旧字、巻の数字、1組ずつ）、運営の道具（まとめる、あとの本もまとまる、戻す、続けてのまとめを逆の順に戻す、外す、別の作品の印がまとめと戻しのあとも正しい作品を指す、動いた本の `updated_at` が変わらない）、退会と控え、戻す SQL と控えからの書き戻し、確かめで止まった工事が全部取り消されること。
- **版の ID**（`20261031000000_edition_ids.sql`）。版は ID で持ち、ISBN は版の属性になった。書誌マスタが ISBN のある版もない版も同じに扱い、作品から外して確かめを待つ登録（次の工事）も自分の版を覚えておけるように。
  - 変わらないこと: 同じ ISBN はその場で同じ版（`editions_isbn_key` で ISBN は1つの版にしかない）。登録のときに題名は比べず、待つのは同じ ISBN の登録が保存の途中にあるときだけ（版の行を押さえる仕組みは同じ。`private.isbn_edition`）。版の ISBN・作品・日付も、本の列と `updated_at` も変えない。
  - 移したこと: 今ある版に ID を付け、本に版の ID（`edition_id`）を入れた。ISBN のない本には、その本だけの版（ISBN なし、今の作品、本と同じ日付）を1冊ずつ作った。本番では、ISBN のない本の数（10-17 には5冊）だけ版が増える。これからの ISBN のない本も、登録のときにその本だけの版と作品ができる。ISBN を消した本も同じ。
  - ISBN のない版は、その本の登録と1対1なので、版の ID も本の ID と同じく公開のリポジトリやログに書かない。
  - まとめは動かした版を覚える（`private.work_joins.editions`）。前からあるまとめには、動かした ISBN の版と、そのとき動いた ISBN のない本の版を入れた。戻すのも外すのも版で動かす。
  - 確かめ（ファイルの中）: 本だけ控え（版は主キーが変わるので `check_copy` で照らせない。前の版は一時の表に写してファイルの中で比べる）、本の列が控えと同じ、どの版も ISBN・作品・日付がそのまま、ISBN のある版が増えていない、ISBN の本はその ISBN の版、ISBN のない本はその本だけの版、本のない ISBN のない版がない、どの本も版の作品にいる、まとめが動かした版（ISBN の版と ISBN のない本の版）を全部知っている。1つでも違えば全部取り消す。
  - 戻すとき: アプリはまだ `edition_id` を読まないので、マイグレーションの頭の SQL（トリガー、まとめの列、本の版、ISBN のない版を消して版の主キーを ISBN に戻す）と、作品と版のファイルの関数を流し直すだけで戻る。ISBN のない本の作品は残る。控え `20261031000000_edition_ids` は本番で確かめ、書誌マスタのマイグレーションで消した。
  - テスト（`tests/db-editions.test.ts`）: 本とまとめのある DB での移す工事（どの行も変わらない、ISBN のない本の版、前からあるまとめの版、控え、見える本が前と同じ、API から版に届かない）、新しい本（同じ ISBN、新しい ISBN、1つの文で2冊、ISBN なし、送り直し、名指しの版は使わない、読書家は自分の文からも版を読めない）、版の行を押さえること（ほかの登録が待つ強さの鍵か、pageinspect で読む）、ISBN を直すと版を移ること、前からのまとめを版で戻す、まとめと戻しと外すの履歴と「別の作品」の印、退会と控え、戻す SQL と控えからの書き戻し、確かめで止まった工事が全部取り消されること。

## 書誌マスタ（2026-10-17、管理表の4）

ISBN のある版ごとに、国立国会図書館（NDL サーチ）と openBD がその本について言っていることを裏側で取ってきて持ち、項目ごとに1つの書誌にする。仕様はけにーさんの見直し（10-16 22:36Z、共有の資料「書誌マスタ　仕様」）。マイグレーション `20261101000000_bibliography.sql`。登録は止めず、本の行も変えない（本は読書家が打ったまま。公開の画面は書誌、本人の棚は本人の入力、をアプリが選ぶ）。食い違いの判定と保留は `20261102000000_bibliography_holds.sql`（下の「食い違いの判定と保留」）、画面は下の「画面」。

- **何を取るか。**
  - 国立国会図書館: NDL サーチの SRU（外部提供インタフェース仕様書 第1.5版）に、ISBN 1つを1回で、図書館自身の書誌だけを聞く（`dpid="iss-ndl-opac iss-ndl-opac-inprocess"`。完成した書誌と作成中の書誌。全国書誌は `iss-ndl-opac` に入っている）。所蔵は聞かない（`onlyBib=true`。答えの大きさは約半分になり、書誌は欠けない）。答えのうち `bibRecordCategory` が R100000002（国立国会図書館）のレコードだけを使い、完成したもの（C7 など）を作成中（C3）より、ISBN の少ないもの（巻）をセットより先に選ぶ。申請なしで使える範囲（仕様の「外の条件」。[外部サービス.md](../開発と運用/外部サービス.md)）。
  - SRU は ISBN をまとめて聞けない（`OR` も `any` も構文エラー。仕様書でも isbn は `=` だけ）ので、20秒に1冊（1分に3冊、1日に最大4,320回）。本が版に入るたびに聞くので、登録が増えると問い合わせも増える。混んでいると 429 が返る（`Retry-After` なし）。それは失敗として、あとで聞き直す。答えは1分待ち、30秒たっても答えのない問い合わせがあるあいだは次を聞かない（下の「問い合わせの辛抱」）。

## シリーズと巻（2026-10-24、管理表の6、`20261204000000_series.sql`）

けにーさんが設計を承認（10-24 07:21Z、設計案 https://claude.ai/artifact/NX1d5KcqcC6FmdmoBLyoVs）。シリーズは作品の上にかぶせる束で、読書家の記録（本・印・ライブラリ）は1つも動かさない。束を作り直しても記録は動かない。

- **4つを分けて持つ。** シリーズ（`series`、「進撃の巨人」全体。BookTown 自身のデータ）＞刊行の並び（`series_lines`、通常版・愛蔵版・文庫版。ほとんどのシリーズは名前のない1本）＞巻（`series_volumes`、並びの中の番号に置いた版）＞版。番号は作品でなく「並びの中の版」に付く。なので通常版1巻と愛蔵版1巻は別に数え、ある版で付けた読了がほかの版の読了に見えることはない。「1〜10巻読了」は、巻ごとの自分の本の記録から数えて見せる（シリーズの側には保存しない）。
- **番号の読み方**（`private.series_number`）: 「3」「第3巻」「[3]」「Vol. 3」「三」は3。上は1、中は2、下は3（中のないシリーズでは2）。「2026年版」「2026年度」は年ごとの種類（`kind = 'yearly'`）の2026で、巻ではない。年版は1冊ずつ別の作品のまま。「続」「別巻1」「1-2」「上下」「総集編」、言葉だけの巻は読まない（候補になる）。
- **図書館のシリーズ欄はレーベル。** 本番の1万冊の見本では、ほとんどが「岩波文庫」のような叢書だった（著者1人の本だけが集まる名前59種類も、多くは叢書）。シリーズを作る元には使わず、並びのラベル（`series_lines.label`）と、候補を見つける手がかりにだけ使う。
- **自動で束ねるのは明らかな物だけ**（`private.series_plan`）: だれでも読める版（目録の行がある。検索と同じ）のうち、題名が同じ・人が同じ（図書館の典拠 ID、ない人だけ名前。役割の書き方は見ない。全員がそろうこと）・出版社が同じ・レーベルと版の言葉（愛蔵版など）が同じ・巻がはっきり読める・同じ番号が2つない、が2冊以上。同じ題名と人のまとまりが複数あれば（通常版と愛蔵版、単行本と文庫）、いちばん多い1つだけ。見本の数（10-24、読むだけで確認）: 巻の欄がある本 2,858冊、題名と典拠が同じで巻が2つ以上の組 294組。著者を役割の書き方まで含めて比べると、同じ人の10組が割れて287組になっていた。
- **候補**（`private.series_candidates`、運営が見て決める）: `unclear`（同じ題名と人で、出版社・レーベル・版の言葉が違う、同じ番号が2つ、上下と数字が混ざる）、`volume`（巻がはっきり読めない版）、`people`（人の顔ぶれが違う、だれも書かれていない）、`label`（1人の本だけが集まるレーベルで題名が違う。ハリー・ポッター型）。
- **人の判断を巻ごとに守る。** 運営の道具（`private.series_make`・`series_add_line`・`series_place`・`series_take_out`・`series_join`・`series_name`・`series_line_name`・`series_finish`。記録は `private.series_decisions`）で置いた巻は `decided = 'human'` になり、規則は動かさない。外した版は `private.series_kept_out` に残り、規則が戻さない。完結は運営が言ったときだけ（`finished_at`）。書誌は完結を言わないので、それまでは「わかっている巻まで」。

  - **見本の行はアプリから書かない**（行はマイグレーションが作ったもの）。
  - **出会い。** 投稿から出会った記録は、投稿の本と同じ版の自分の本（写し）を指してもよい（`check_book_encounter`）。
- **気をつけること。** 2本目が本番に入る前に置かれた送り待ちの変更や、前の版のアプリを開いたままのページから、ほかの人の本を指す書き込みが届くと、DB が断る（断られた変更として知らせ、書きかけは戻す）。2本目のトリガーがある間は、`private.give_own_copy` で付け替えをやり直せない（ポスターの本を付け替える途中で、まだ写していない本を指す行をトリガーが断る）。もう一度付け替えるときは、トリガーを外してから流し、終わったら戻す。店内の飾りつけは街とは別に送るので、つながらないあいだに写しを作った本を置いて保存すると、つながったときに写しより先に店内が届いて断られることがある（書きかけは残り、もう一度保存すれば通る）。
- **戻すとき。** それぞれのマイグレーションの頭の「Rollback」（1本目は関数と表を外し、`touch_updated_at` を元に戻す。2本目はトリガーと関数を外し、`check_book_encounter` を元に戻す）。写しはその人の登録として残る。付け替えそのものを戻すときは、頭の2つ目の注記の `restore_copy` と削除を、付け替えのすぐあと、だれもその表に書いていないうちに流す（`restore_copy` は表の行を全部控えの値に戻すので、あとからの書き込みも戻り、削除は写しを指す行を全部消す）。控えは本番で確かめてから、別のマイグレーションの `drop_copy` で消す。

## 表紙

- **取り元の順。** 表紙は ISBN のある本だけ、openBD → Google Books の順に探し、どちらにもなければ題名と著者から作る「装丁カード」を出す（`src/lib/covers.ts`）。取得元を足すときは `COVER_SOURCES` に順番どおり加える。Google の `isbn:` 検索が 2026-10 から空で返るので、Google には題名で先に聞き、同じ ISBN の本だけを使う（`googleQuestions`）。取得元ごとの使い方の決まり（そのまま出す、Google の表示とリンク、ブラウザに残さない、API キー）は [外部サービス.md](../開発と運用/外部サービス.md)。
- **保留の本とほかの人の本。** 保留の本は ISBN の表紙を出さず、ほかの人の本は書誌が出てから表紙を探す（`useCoverIsbn`、上の「画面」の「保留の本の表紙」）。
- **作らないもの。** 店主が撮った表紙の写真は作らない（けにーさん 10-13 00:46Z「絶対やめたほうが良い」）。AI のあらすじは、作ってもよいと言われている（けにーさん 10-19 12:20:43Z「あらすじはAIでつくってもいい」）が、今は管理表に足さず保留（10-19 12:28Z、けにーさんがカードで「足さない」）。

### 表紙の削除依頼

- 表紙の出どころ（「表紙: openBD」「powered by Google」）の下に、小さく「表紙の削除依頼はこちら」。ログインしている人にだけ出す（招待制なので、ログインしていない権利者は依頼できない。押してもログインの案内にしかならないため、出さない）。権利者がアカウントなしで依頼できる窓口は、まだない。本についての通報（`target_kind = 'book'`、`reason = 'cover'`）として届き、説明は必須。アプリが「表紙の出どころ: Google Books / ISBN …」を説明の後ろに足す。
- 運営が受けると `cover_refusals` に ISBN と取得元を入れる。アプリはページを開くたびにこの一覧を読み、その本についてはその取得元に問い合わせない。次の取得元の表紙か、装丁カードになる（画像に手を加えない決まりは [外部サービス.md](../開発と運用/外部サービス.md)「表紙の出し方の決まり」）。一覧が読めないときは、そのページでは外の表紙を出さない。
