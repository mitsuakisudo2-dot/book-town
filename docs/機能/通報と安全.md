# 通報と安全

通報、運営が隠すこと、通報が集まったときにたたむ仕組み、ネタバレのたたみと表示の正本です。ブロックとだれが何を読めるかは [公開範囲.md](./公開範囲.md)、表紙の削除依頼は [本と書誌.md](./本と書誌.md)「表紙の削除依頼」にあります。docs/09 から移した節です。

## 運営（通報と非表示）

- **ログインしている人は、ほかの人の投稿、本屋、プロフィール、ポスターを通報できる。** 本の表紙は、同じ通報の表に理由「表紙」で届く削除の依頼で、たたむ仕組みには入らない（[本と書誌.md](./本と書誌.md)「表紙の削除依頼」）。 理由（宣伝・スパム、嫌がらせ・攻撃的な言葉、個人情報をさらしている、脅し・危害を加えるという言葉、不適切な内容、その他）と、任意で1000文字までの説明。ネタバレは通報ではなく「ネタバレでは？」で伝える（下の「ネタバレのたたみ」）。通報したことは相手に知らされない。同じものへの通報は1人1回。自分自身は通報できない。ログインしていない人には、ログインへの案内を出す。見本（デモ）には通報のボタンを出さない。
- **運営は Supabase の画面で通報を読む**（SQL Editor で未対応の一覧を出す。手順は共有フォルダの「運営の手順_通報と非表示」）。
- **本当に隠すのは運営だけ。** 運営が `moderation_hides` に行を足すと、その投稿、本屋、人（その人の本屋、投稿、人生の9冊、一緒に読んでいること、本屋に残したひとことも）が、本人以外から見えなくなる。通報が集まって自動で起きるのは「たたむ」ことと、深刻な理由での「確認まで見えなくする」ことだけ（下の「通報とたたむ仕組み」）。2026-10-13 までは3人の通報で自動で隠れていたが、捨てアカウント3つで誰の投稿でも消せたため、やめた。
- **ネタバレのたたみ。** 目印のない投稿に別々の3人が「ネタバレでは？」（`spoiler_reports`）を押すと、`posts.spoiler_folded` が立ち、全員の画面で「ネタバレあり」と同じようにたたまれる（タイムラインでは覆い、作品ページでは扉の向こう）。消えはしない。誰が押したかは本人以外に見えない。書いた人には「たたんで表示しています」とお知らせが1回届き、自分で「ネタバレの印を付ける」ことができる（付けた印は外せない）。押した人が取り消すと、3人を切ったところで元に戻る。運営が戻すときは `spoiler_reports` のその投稿の行を消す。理由が spoiler の通報（古い画面から届いたもの）は数えても隠さない。
- 投稿の本文は、書いたあとは本人も変えられない。変えられるのは、ネタバレの印を付けることだけ（列の権限で `spoiler` だけ）。
- 隠す判断は RLS の `private.is_hidden()` が行う（`moderation_hides` と、`moderation_folds` の `held`）。`private` スキーマは API に出ないので、外から呼べない。`moderation_hides` は運営（service role）だけが読み書きできる。
- まだないもの（管理表43 の残り。どれも DB を触る）: 運営の画面（通報を見て隠す・戻すをスマホで）、禁止語、連続投稿の制限、ブロックの抜けの直し（[公開範囲.md](./公開範囲.md)「まだ DB で止めていないこと」）。運営が隠すと決めたこと（`moderation_hides`）を本人に知らせる表示、通報が来たときに運営へメールで知らせる仕組み（送信元のドメインが決まってから）。自動でたたんだこと・確認まで見えなくしたことは、書いた人に知らせている。

## 通報とたたむ仕組み（2026-10-13）

規則はデータベースの1か所（`private.weigh_report` と `private.review_state`、`supabase/migrations/20261022000000_safety_defaults.sql`）にある。

- **3人分の通報で、たたむ。消さない。** 作って7日以上のアカウントの通報は1人分、7日未満は半人分。作られた時刻が24時間以内につながるアカウント同士は、何件あっても合わせて1人分まで。合わせて3人分になると `moderation_folds` に `folded` が立ち、みんなの画面で「通報があったため、運営が確かめるまで、たたんでいます」になる。押せば読める。ポスターも同じで、タイムラインのカードとポスターのページでは、ポスター（ページでは載っている本の一覧も）の前に覆いがかかる。押して読んだあとも、ネタバレの印があれば扉は残る。プロフィールと作品ページの小さな一覧では「たたんでいます」と理由（「通報があったため」）だけを出し、見出しも本も出さない（読み上げの名前は見えている言葉どおり「ポスター たたんでいます（通報があったため）」、ページの見出しは「たたんでいるポスター」）。投稿も、押して読むまでは添えた本を出さない。本屋と人は、紹介文だけをたたむ（名前、棚、POP、投稿はそのまま。それぞれに通報がある）。
- **すぐ見えなくするのは、深刻な理由だけ。** 理由が「個人情報をさらしている」「脅し・危害を加えるという言葉」で、通報した人のアカウントが作って7日以上なら、投稿とポスターは運営が見るまで本人以外から見えなくなる（`held`）。1人が24時間に急ぎにできるのは3件まで。本屋と人は、たたむだけ。
- **画面のたたみは、投稿もポスターも同じ判定。** みんなの画面の覆いは `reviewCoverOf`、書いた人への書き添えは `reviewNoteOf`（`src/lib/social.ts`）。
- **アカウントの古さ**は `greatest(auth.users.created_at, profiles.created_at)`。`profiles.created_at` はプロフィールを作ったときにデータベースが付け、本人は変えられない（`private.stamp_profile_time`。変えられると、同時に作ったアカウントが日付を1日ずつずらして別々の人になれる）。招待はけにーさんが同じ日にまとめて作ることが多いので、`auth.users` だけだと最初の読書家たちが1人分にまとまる。プロフィールは各自の初めてのログインで作られるので、遅いほうを使う。
- 急ぎになる通報は、同じ人の通報を1件ずつ数える（同時にたくさん送っても、急ぎは24時間に3件まで）。
- **通報の状態**は運営だけが変える。通報した人には、これだけが届く（相手をどうしたかは伝えない）。通報した人が読めるのは `status` ではなく `progress`（`open`・`checking`・`checked`）で、`resolved` と `dismissed` はどちらも `checked` になる。

| `status`    | 意味                   | 通報した人に見える言葉 |
| ----------- | ---------------------- | ---------------------- |
| `open`      | 届いた、まだ見ていない | 受け付けました         |
| `checking`  | 運営が見ている         | 確認中                 |
| `resolved`  | 対応した               | 確認しました           |
| `dismissed` | 問題なし               | 確認しました           |

- **書いた人には、たたまれたこと・見えなくなったことが届く**（誰が、何人かは伝えない）。運営が `dismissed` にすれば、たたみは自然に戻る。通報した人の画面では、通報したものは結果にかかわらずたたんだまま（「あなたが通報した投稿です」「あなたが通報したポスターです」）。書いた人の投稿・ポスターの下には、たたまれていること（「…ポスターは消えていません。」）や、確認まで見えなくしていることを書き添える。ポスターは、作った人のプロフィールと作品ページの小さな一覧（「通報があり、みんなの画面ではたたんでいます」「運営が確かめるまで、ほかの人には見えません」）と、直す画面にも書き添える。お知らせでは、投稿は本文の書き出しで、ポスターは見出し（なければ本の題名）で名指しし、2つあっても見分けられるようにする。
- **消したものは、たたみも残さない。** 書いた人が投稿・ポスター・本屋を消すと、その `moderation_folds` の行も消える（`private.refold_taken_down`。行の持ち主がいなくなったものは、通報の状態が変わっても行を作り直さない）。通報の行は運営のために残る。
- 通報した人は、自分の通報の id、種類、理由、`progress`、日時だけを読める（`status`、`detail`、`urgent`、`reporter_id` は読めない）。お知らせの「あなたの通報」に1行ずつ並ぶ。確認中・確認しましたのお知らせは「{もの}について{M月D日}にいただいた通報を、運営が確認しています」の形にする（何についてかを先に書く。「…にいただいたポスター」は「いただいたポスター」と読め、「通報してくださった読書家を」は通報した人が確かめられているように読めるため）。表紙は「表紙について{M月D日}にいただいた削除の依頼を、…」。

## ネタバレの表示

- 設定で3つから選ぶ（`reader_settings.spoiler_display`。行がなければ真ん中）。ログインしていない人は真ん中。言葉と意味はけにーさんの決定（2026-10-16 05:43Z「ネタバレをどう避けたいかは人によって違うから選べるように」）。値の名前は前のまま。
  - すべて表示する（`show_all`）: 書いた人の印も、3人以上の「ネタバレでは？」も、読んだところに関係なくそのまま出す。2026-10-27（管理表22 ①）までは、3人分のたたみだけを開き、書いた人の印はたたんでいた。
  - 読んだところより先のネタバレは、たたんで表示する（`fold_possible`、はじめはこれ）。押すと読める。
  - 読んだところより先のネタバレは、一覧にも出さない（`leave_out`）: タイムライン、作品ページ、返信、読書記録のひとことから外す。作品ページには「設定により出していません」と1行だけ出す（件数は出さない）。
- 自分が「ネタバレでは？」と言った投稿は、どれを選んでも自分の画面ではたたむ（出さない設定なら出さない）。自分の投稿は出さない対象にしない。
- **読んだところまでのネタバレは、そのまま読める**（2026-10-14、2026-10-27 に巻へ広げた）。範囲のない印と3人分のたたみは、その本（`finishedBooks`、同じ作品のほかの版も）を読み終えた人に開く。範囲のある印は下の「ネタバレの範囲」のとおり。どの設定でも（出さない設定でも）開いて出す。もう知っている人に、たたむ理由がないため。自分が「ネタバレでは？」と言った投稿だけは、読み終えたあとも自分の画面ではたたんだまま。返信は本を持たないので、返信先の投稿の本で決める（`spoilerBookOf`）。通報でたたんだもの（上の「通報とたたむ仕組み」）は、この決まりでは開かない。
- たたんだ投稿の箱は、本文を1文字も出さず（ページの中にも置かない）、どの本の話かだけを伝える1つのボタンにする。押すとその場で開く。言葉は、隠していることより、いつ自分から開くかを言う（2026-10-27）。
  - 書いた人の印、範囲あり: 「5巻まで読むと開きます・押すと表示」。横の札は「5巻までのネタバレ」。
  - 書いた人の印、範囲なし（巻のない本、シリーズの巻がまだ読めていないとき）: 「読み終えると開きます・押すと表示」。札は「ネタバレあり」。
  - 3人分: 「ネタバレかもしれません・押すと表示」。自分の「ネタバレでは？」: 「ネタバレの可能性を報告済み・押すと表示」。
- ポスターは作った人の印（`posters.spoiler`）だけを見る（「ネタバレでは？」も範囲もない）。印があれば扉の向こう、すべて表示するなら開く、出さない設定ならタイムライン、プロフィール、作品ページに並べない。作品ページには「ネタバレを含むポスターは、設定により出していません」と1行だけ出す。アドレスから直接開いたときは、扉の向こうに出す。自分のポスターは出さない対象にしない（`posterSpoilerView`、`src/lib/posters.ts`）。
- 読書記録のひとことの印（`reading_entries.spoiler`）は、本人、その本を読み終えた人、すべて表示する人に開く（`recordNoteView`、`src/lib/records.ts`）。範囲はない。
- 判断は `spoilerViewOf`（`src/lib/social.ts`）の1か所。

## ネタバレの範囲（2026-10-27、管理表22 ①）

けにーさんの決定（2026-10-16 05:33Z「10巻までの読者と安心して語りたい」、10-25 00:24Z に手で選ぶ分を先に分けた）。読んだ巻から自動で付ける分（②）と AI の網（③）はまだ。

- **書く人。** 投稿（感想と返信）で「ネタバレあり」を付けると、その本がシリーズの巻なら、その下にシリーズの背表紙が並ぶ（`SpoilerRangeShelf`、`src/components/SpoilerRange.tsx`）。並ぶのはその巻から、わかっている最後の巻まで。触った巻まで帯がかかり、「5巻までのネタバレ」と出る。最初は最後の巻（「全巻」、完成条件「初めは全巻」）。巻のない本、シリーズの最後の巻、返信先が本を持たない返信では背表紙は出ず、今までどおり「ネタバレあり」だけ。
- **持ち方。** `posts.spoiler_through`（巻の番号、`series_volumes.number`。その本が入っている並びの番号）。「全巻」は書いたときの最後の巻の番号で持つ（あとで出た巻のネタバレは書けないため）。空は範囲なし（前からの投稿、巻のない本、あとから付けた印）で、今までの印と同じ。範囲は書いたときだけ書け、あとから変えられない（あとから付ける印は範囲なし、いちばん広い）。印のない投稿には付けられない。マイグレーション `20261214000000_spoiler_ranges.sql`。
- **読む人。** その本の並び（`series_for_isbn` で読む。範囲のある投稿が町にあるときだけ、その本の分だけ）で、読み終えた巻（ISBN が同じ本か、同じ作品の本）のいちばん大きい番号が範囲以上なら開く（`readFarEnough`、`src/lib/spoiler-range.ts`）。10巻を読み終えた人は1〜9巻も読んだとみなす。並びがまだ読めていないとき、本がどの並びからも外れたときは、読んだところでは開かない（安全な側。たたむか、出さない設定なら出さない）。並びは画面のために読むだけで、町には残さない（`useSpoilerLines`、`src/lib/store.ts`）。読んだ巻はサーバーに送らない。
- **DB より先にアプリが出たとき。** 範囲のある投稿を書くと列がないと断られるので、範囲を外して（全巻として）書き直す（`town-backend.ts` の posts）。
- **まだ持たないもの。** POP（30）・ポスター（31）・掲示板（56）の範囲（作るときにこの部品を使う）、読書記録のひとことの範囲、版の並びをまたいだ読了（文庫版と通常版は別に数える）。
- **テスト。** `tests/spoiler-range.test.ts`（選べる巻、読んだところ、開く・たたむ・出さない、並びが読めないとき、箱の言葉、読む並び、下書きを合わせると広い方、範囲は印のある投稿だけ）、`tests/domain.test.ts`（3つの表示）、`tests/town-remote.test.ts`（書く行と読む行）、`tests/database-policies.test.ts`（印が要る、番号は1から、あとから変えられない、あとから付けた印は範囲なし）、`tests/login-journey.mjs`（背表紙で選んで投稿し、箱の言葉を見る。画像 `22-spoiler-range-*`・`22-spoiler-cover-*`）。
