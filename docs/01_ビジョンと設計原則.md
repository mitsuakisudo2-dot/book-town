# ビジョンと設計原則

更新日: 2026-10-10　状態: 第1回三者会議を反映

## 0. 名前
「余白」は**仮称**。正式名称を決定したものではない。本書では便宜上「本サービス」と呼ぶことがある。

## 1. なぜ作るのか

- **ミッション（決定）**: 「本を愛する人を、孤独にしない。」
- **コンセプト（決定）**: 「本を読みたくなるSNS。」
- **体験の指針**: 「読書の終わりを、交流の始まりに。」
- **関係の指針**: 「あなたの愛した一冊が、誰かの愛する一冊になる。」
- **探索の指針**: 「本屋を歩くように、誰かの世界を歩く。」
- **偶然の出会い**: 「本を探していたら、人に出会った。」
- **居場所**: 「本を読む時間も、読まない時間も、読書家でいられる場所。」

「読後の感想」だけに限定しない。最近読めていない人、積読が増える人、読書灯や書店巡りについて語りたい人も読書家である。読了が参加資格になる設計は避ける。

## 2. 三者が共有した中心思想

### 本と本をつなぐのは、人間の感性である【決定】

「このジャンルが好きならこの本」という機械的関連だけでなく、「ある人がこの一冊を薦め、その人がほかに何を選んだか」に価値がある。

例: 『星を継ぐもの』→紹介者A→Aが大切にする『夜と霧』→別の紹介者B→別の本。

**推薦対象は書籍だけでなく、その本を選んだ人・置かれた棚・POP・推薦理由の組み合わせ。** 誰かの本棚を見に来た人が、知らない本へ、そして人へと移動できる体験を設計する。

### 本棚を作るのは人間。街に道を作るのがアルゴリズム。【決定】

- 棚の掲載本、配置、並び順、背表紙／面陳、POPは店主の編集表現。アルゴリズムは勝手に並べ替えない。
- アルゴリズムは店主の意図を尊重しつつ、店と店、人と本の間に探索経路をつくる。
- 読書家の自由なコメント・推薦が新しいつながりを作り、アルゴリズムはその道を**発見可能にする**。

### 街の雰囲気はユーザーが作る【決定】

運営が「静かな街」「賑やかな街」を決めて画一化しない。読書家の本の選び方、POP、看板、棚の編集、許可された活動から文化が育つ。

> 街をデザインするのではなく、街が育つ仕組みをデザインする。

一方、アクセシビリティ・操作の一貫性・プライバシーはプラットフォームが守る。

### 本屋にずっといたい【決定】

目的を持たずに歩いても新しい本と出会える、**本探しの無限スクロール**を重視する。ただし、ただ眺め続けるための刺激を最大化しない。スクロールの価値は「本を読みたくなった」「誰かの感性と出会った」「新しい話を知った」ことで測る。

## 3. 操作のメタファー【強く支持された方向性】

| UI操作 | 現実の行動 |
|---|---|
| 縦スクロール | 通りを歩く／次の書店へ |
| 横スクロール | 棚を眺める |
| 本をタップ | 一冊を手に取る |
| 手に取った状態で横スワイプ | 隣の本を手に取る |
| 開いた本を閉じる | 元の棚の同じ位置に戻す |

書店の外観や棚が主役。店と店の間に公開許可された小さな「足跡・出来事」を出すことは有力案だが、投稿全文を混ぜて通常のタイムラインに戻さない。SNSには独立した入口も設ける方向。

## 4. 個人書店の編集

- **1人2棚程度**: ユーザーからの強い提案。ただし容量との兼ね合いを実機検証して確定する【有力案】。
- **1棚15〜20スペース程度**: 仮の実験範囲【有力案】。背表紙と面陳の占有差も重要。
- **一冊から始める**: いきなり完成棚を要求しない【有力案】。
- **展示と記録を分ける**: 棚から外した本の蔵書・読了・読みたい記録は消さない【合意した方向性】。
- **一冊を選ばないことにも意味がある**: 数の制限は選書の質と店主の編集意図を高める。
- **棚替えは小さなニュース**: 再訪の理由となる。ただし活動を街へ通知する範囲は店主が決める。

## 5. 行動と感情を混同しない【決定】

| 行動 | サービスが事実として言えること |
|---|---|
| 読了登録 | 「読みました」 |
| 棚へ陳列 | 「並べています」 |
| POPを記載 | 「この視点から紹介しています」 |
| 読みたい登録 | 「読みたいと思っています」 |
| お気に入り／人生の9冊 | 本人が大切にしていると表明した作品（用語の定義を検討） |

棚に並べたから「愛しています」と断定しない。「POPを経由して保存した」というログと「そのPOPのおかげで読みたくなった」という意思表示も区別する。

## 6. SNSと交流

自由な読書家の日常投稿も歓迎する。書籍感想に限定しない。

**2026-10-11 決定**: 本の街と並び、TwitterやInstagramのように自由に投稿・交流できるSNSを柱にする。目指すのは「この人の呟きが好きだから、この人が好きな本を読んでみたい」と思える場所。投稿仕様・ネタバレ・設計判断は [05_SNS基盤_仕様と設計判断.md](./05_SNS基盤_仕様と設計判断.md)。

読書家が自然に交わしたい言葉:
- 「あなたのおかげで出会えた！」
- 「買う！ 面白そう！」
- 「この本と似てない？」
- 「この本も好きなんじゃない？」

**お礼・軽い一言・本を添えた推薦・読了後の報告**をできるだけ軽くする。店主の棚そのものには反応数やコメントの密集を避け、本を手に取った画面から交流につなげる。

非公開の付箋（店主宛て）と公開の会話（作品／POPを囲む）はどちらも有力案。ただし構造、匿名の扱い、受信設定、コメントの所属単位は未決定。

## 7. 非同期交流

作品について残された言葉は、何年後でもほかの読者が発見でき、返事を返せる。「未来の読者への手紙」構想。

- 投稿データ基盤は一般投稿と共有してもよい。
- 表示・公開・ネタバレ保護は区別する。
- ネタバレは既定で保護し、読了登録や本人の明示操作で開ける案。
- 手紙をタイムラインにどう載せるかは未決定。

## 8. 少人数でも成立する設計

> 「その機能は、ユーザーが10人しかいない日に、誰かの孤独を減らすか？」

初期には未訪問の書店を優先するなど単純な道を用意する。書店を歩き尽くしたら、まだ人のPOPがない書籍情報や「空き地」を**人が推薦したかどうかを明示して**見せる案がある。

存在しない人・感想・活動・店舗数を作って賑わいを偽装しない。推薦候補の不足を高度なAIだけで解決できると思わない。初期に多様な読書家を招くことも重要。

## 9. プライバシー、本人の自由【決定】

- 匿名投稿から個人書店や本名／プロフィールへ結び付く活動表示を行わない。
- 読書中・読了・読書状況は既定で非公開。出来事単位の公開には本人の意思が必要。
- 「読みたい」の行動を勝手に公開したり、紹介者に通知したりしない。
- 店主は受信設定やブロックで交流を制御できるようにする。
- 書店の任意の閉店と、アカウント退会・削除は別の処理。本人が削除した痕跡を不必要に残さない。
- 表示順は人気一辺倒にせず、新人の小さな書店の発見機会を確保。本人が自主的に再訪することは妨げない。

## 10. 議論を保留した事項

課金・収益化・棚枠追加課金は**保留**。確定事項として扱わない。

個別画面、SNS投稿の詳細仕様、検索、書籍マスタ、タイマー、選書マッチング等も段階的に議論する。既存のプロトタイプは叩き台であり、完成仕様ではない。
