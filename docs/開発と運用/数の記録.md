# 数の記録

読書家の使い方を、だれの分か分からない1日ごとの回数で知る仕組み（つまずきの数、タブの回数）の正本です。人・時刻・順番は残さず、API からはだれも読めず、Claude が毎週の点検で作業環境の接続（select だけ）から週の合計を読みます。どちらも20回に届かない欄は数を出しません。毎週の読み方は [監査/README.md](../監査/README.md)、DB の変え方は [DBの変え方.md](./DBの変え方.md) にあります。

新しい数を足すときも、この資料に節を足します（docs/09 には足しません。AUD-199・AUD-203）。

## つまずきの数（2026-10-27、管理表110）

読書家がどの機能でつまずいているかを、だれの分か分からない1日ごとの回数で知る（けにーさん 10-18 12:02Z。作り方の案は共有の資料「つまずきの数え方_案_2026-10-18」）。

- **残すのは日・機能・結果・回数だけ。** 置き場は `private.stumbles`（マイグレーション `stumble_counts`）。送る関数 `count_stumbles(features, results, times)` は、決まった言葉の3つの並びと小さな数しか受け取れず、人・時刻・アドレス・入力した言葉・本を入れる欄がない。1日の行は 機能4 × 結果5 = 20行まで。
- **機能**（`src/lib/stumbles.ts` の `STUMBLE_FEATURES`）:
  - `search` 本の検索: 入力が0.3秒止まって DB に聞いた（`find_books`）1回。打っている途中の短い言葉も1回になり、見つからないになりやすい。同じページで同じ言葉をもう一度聞くと数えない（答えを覚えている）。失敗した1回は5秒後に1回だけ聞き直すので、2回と数える。
  - `register` 本の登録: ライブラリに新しく入る本の保存（`library-entries` の新しい行のある書き込み）1回。読書の状態を変えるだけの保存は数えない。本の冊数ではなく書き込みの数で、連続スキャンでまとめて30冊入っても1回。同じ書き込みに入った状態の変更が断られても「断られた」になる。
  - `barcode` バーコードの読み取り: カメラが ISBN を読んだ1回（できた。3秒より離れて同じ本を読み直しても1回）、カメラを読書家が許さなかった（断られた）、カメラか読み取りの準備が使えなかった（そのほか）。読んだ本を openBD が知らなかったとき（見つからない）は、その「できた」に重ねて数えるので、試した回数より多めに出る（失敗の割合には入らない）。手で打った ISBN は数えない。
  - `shelf` 本棚の保存: 書店の棚・店内（`shelves`・`scene`）と自分で作る棚（`library-shelves`・`shelf-books`）の保存1回。
- **保存の数え方**（`src/lib/supabase/sync.ts` の `stumble`）: まとめて送る1回の書き込みごとに、全部入った（できた）・一部でも断られた（断られた）・ほかの端末で変わっていた（そのほか、読書家の変更は入らなかったので失敗に数える）のどれか1つ。送り直す失敗は、答えがなかった（つながらない）と、サーバーの都合（混んでいる・時間切れ・ログインが切れた。そのほか）に分け、送り直すたびに数える。アプリの都合で待つ（町を読む前、店がまだ保存されていない）のは数えない。送り直した回は、前に数え終えた書き込みを数え直さない。前のページが端末に残した書き込みを次のページが送ると、そこでもう1回数える。
- **失敗の言葉**（`stumbleOf`）: 断られた＝ DB の決まりに断られた（送り直さない失敗）。つながらない＝答えが来なかった。そのほか＝それ以外。
- **送り方。** 端末の中でためて、5分ごと、できた以外の結果のあと20秒、画面を離れたときにまとめて送る。オフラインの間は送らず、送れなかった分は次に送るまで待つ（ページを閉じたら捨てる。ログアウトとアカウントの切り替えでも捨て、次の人の分に混ぜない）。ログインしている人の分だけ（関数は authenticated だけが呼べる。ログインしていない人の操作は数えない）。読書管理モードの人も数える（けにーさん 10-18 12:07Z）。つながらないは、その機能がほかの結果になるまで1回と数える（待っている間の送り直しで増えない）。1回の呼び出しで1つの行に足せるのは100まで、1行は1億で止まる。
- **消す。** 90日より前の行は、毎晩 03:47（日本時間、pg_cron の `stumbles`）と送られたときに消える。退会で消すものはない（誰の行でもない）。
- **見る。** API からは誰も読めない。毎週の点検で Claude が Supabase の接続（select だけ）で週の合計を読む。日ごとの数は見ない。試した回数が20回に届かない欄は数を出さない（`under_20`）。週と月は別々に伏せるので、月から見えている週を引けば伏せた週の数は分かる。だれの分かは残していないので人には結びつかないが、伏せた欄を引き算で出して人に見せない。表そのものを日ごとに読まない。見つからないは失敗に入れず、失敗の割合（`failed_share`）は見つからない以外のうちの割合。

    `private.stumble_totals('week')` が週（`'month'` で月）の合計を返すが、作業環境の接続（読むだけの役）には実行の権限がない（関数は誰にも開いていない）。接続からは同じ中身を select で読む（2026-10-27、本番で確かめた）。

    ```sql
    select date_trunc('week', day)::date as starts, feature,
      case when sum(times) >= 20 then sum(times) end as tries,
      case when sum(times) >= 20 then coalesce(sum(times) filter (where result = 'ok'), 0) end as ok,
      case when sum(times) >= 20 then coalesce(sum(times) filter (where result = 'not_found'), 0) end as not_found,
      case when sum(times) >= 20 then coalesce(sum(times) filter (where result not in ('ok', 'not_found')), 0) end as failed,
      sum(times) < 20 as under_20
    from private.stumbles group by 1, 2 order by 1 desc, 2 limit 20;
    ```

- **数だけで決めない。** 失敗の割合が上がったら、けにーさんの注釈や聞き取りで中身を確かめる。
- **戻す。** マイグレーションの頭に書いた5行を新しいマイグレーションにする（表と関数を消すだけで、ほかの機能に影響しない。アプリは送れなかった分を黙って捨てる）。

## タブの回数（2026-11-01）

スマホの下のタブ（ホーム・検索・書店めぐり・ライブラリ・記録・わたし）のどれが何回押されるかを、だれの分か分からない1日ごとの回数で知る。下のタブを6のまま β に出し、数を見てから減らすか決めるため（けにーさん 11-01 11:45Z「とりあえず下は6。ベータとかでどれが何回押されるかを計測しとこう」）。作りは上の「つまずきの数」と同じ。

- **残すのは日・モード・タブ・回数だけ。** 置き場は `private.tab_taps`（マイグレーション `tab_taps`）。送る関数 `count_tab_taps(modes, tabs, times)` は決まった言葉と小さな数しか受け取れず、人・時刻・押した順番・元いた画面を入れる欄がない。1日の行は モード2 × タブ9 = 18行まで。
- **数えるもの**（`src/lib/tab-taps.ts` の `TAB_TAP_TABS`）: 下のタブ6つ（`home` `search` `walk` `library` `reading` `profile`。読書中に「読書中」と出ている間も `reading`）と、上の帯のボタン3つ（`top_add` 本を登録、`top_bell` お知らせ、`top_me` 右上の顔）。右上の顔は「わたし」と同じページを開くので、どちらが使われているかを比べられるようにした。いま開いているタブをもう一度押した（一番上に戻る）のも1回。
- **モード**（`TAB_TAP_MODES`）: `town` ふつうの街、`manage` 読書管理モード（タブは5つで書店めぐりがない）。
- **数えないもの。** 広い画面の横のナビ（スマホの並びを決めるための数なので）。数えるのは下のタブが見えている間だけで、上の帯のボタンも同じ。ログインしていない人の操作。
- **送り方。** 端末の中でためて、5分ごとと画面を離れたときにまとめて送る。オフラインの間は送らず、送れなかった分は次に送るまで待つ（ページを閉じたら捨てる。ログアウトとアカウントの切り替えでも捨てる）。1回の呼び出しで1つの行に足せるのは200まで、1行は1億で止まる。
- **消す。** 90日より前の行は、毎晩 03:49（日本時間、pg_cron の `tab-taps`）と送られたときに消える。
- **見る。** API からは誰も読めない。Claude が Supabase の接続（select だけ）で週の合計を読む。20回に届かない欄は数を出さない。日ごとの数は見ない。

    ```sql
    select date_trunc('week', day)::date as starts, mode, tab,
      case when sum(times) >= 20 then sum(times) end as taps,
      sum(times) < 20 as under_20
    from private.tab_taps group by 1, 2, 3 order by 1 desc, 2, 4 desc nulls last limit 40;
    ```

- **タブを足すとき**（上の帯に DM や左上のメニューを足すなど）: `TAB_TAP_TABS` に1語足し、関数と表の2つの一覧に同じ語を足す新しいマイグレーションを書く（1日の行の上限 18 も直す）。`tests/db-tab-taps.test.ts` が一覧の食い違いを止める。
- **数だけで決めない。** 押されないタブは「要らない」とも「見つけにくい」とも読める。けにーさんの注釈や聞き取りと合わせて決める。
- **戻す。** マイグレーションの頭に書いた4行を新しいマイグレーションにする（ほかの機能に影響しない。アプリは送れなかった分を黙って捨てる）。
