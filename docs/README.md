# BookTown の資料の索引

BookTown（旧仮称「余白」）は「本を通じて、人と出会うSNS」です。一人ひとりが自分の本屋を開き、その本屋が並んで街になります。

情報の種類ごとに、詳しく書く資料（正本）を1つだけにしています。ほかの場所は正本を指すだけです。作業を始めるときは、リポジトリ直下の [CLAUDE.md](../CLAUDE.md)（いつ何を読むかと、してはいけないこと）、この索引、[開発の手順](./開発と運用/開発の手順.md) の順に読み、あとは作業に関わる正本だけを読みます。

## 資料どうしが食い違うとき

特定の資料を無条件に優先しません。同じ事実は、その種類の正本にだけ詳しく書き、ほかの場所は正本を指すだけにします（2026-10-22 から、移した種類の順に）。

1. まず、その事項の正本がどこかを確かめます（下の「リポジトリの外にあるもの」も含む）。
2. 今どう動いているかは、今のコードとテストで確かめます。
3. 正式な仕様や運用の判断は、それぞれの正本に従います。たとえば取り込みと本番への反映の了承は、リポジトリの外の運営の指示が正本です。
4. それでも食い違いが解けないときは、推測で変えず、ユーザーに確かめてください。見つけた食い違いは報告してください。

## リポジトリの外にあるもの

次のものはリポジトリに置いていません。見られないときは推測で埋めず、ユーザーに聞いてください。

- **作業の進め方と承認の決まり**（取り込み・本番への反映の了承など）: 運営のプロジェクトの指示にあります。
- **機能一覧と作る順番**（資料に出てくる「管理表5」などの番号）: 運営の共有フォルダの管理表にあります。
- **今だれが何を作っているか**: 運営のプロジェクトのスレッドの一覧と、GitHub の開いている PR で見ます。リポジトリの中では `git branch -r --no-merged origin/main` が手がかりになりますが、だれが作業中かまでは分かりません。ほかの作業が触っていそうなファイルは、触る前に聞いてください。
- **まだ直していないセキュリティの問題の中身**: 公開のリポジトリには書きません（[監査/README.md](./監査/README.md)）。

## 資料の読み方の印

- **決定**: ユーザーが明確に支持した方針。実装時に尊重する。
- **仮決め**: 目標や仮の値として合意したが、確定ではない。
- **提案**: 出た案。承認済みの要件ではない。
- **未決定**: 実装前に判断が必要な事項。

これらを混同しないでください。

## 作業するときの注意

- 資料を読んだだけで全機能を実装しないでください。頼まれた範囲だけを変えます。
- 仕様が食い違ったら、ユーザーのはっきりした最新の指示を優先し、合意していない部分を決め打ちしません。
- 実装済み・試作・構想のみを区別して報告します。確かめていないことを確かめたと書きません。
- 公開リポジトリなので、個人情報・API キー・秘密の設計情報を書き足しません。
