# UI構成 — 下のバー・ホーム・読書・プロフィール

日付: 2026-10-10 / 提案: ユーザー / 名称: 「余白」は仮称

ユーザーが示したUIの構成と、それに対する確認・決定、試作での実装状況をまとめる。**この文書は実装指示ではない**。

## ユーザーの提案（原文の要約）

下のバー（スマホ基準）は左から順に:

1. **ホーム** — 本棚とタイムラインをスワイプで切り替える。タイムラインに投稿するボタンは右下の丸いボタン。ペンのマークだと本っぽくて可愛い。タイプライターなど、設定で変えられたら可愛い。本を添えるボタンはとても良いが、検索機能がない。
2. **検索** — 本と書店の検索。人気の本や話題の本。マイナーな本も探せるように。
3. **読書を開始** — これから読む本を選ぶ。リアルタイムで読書メモ兼つぶやきができる。今読んでいる本を初期選択にして、選ぶ手間を減らす。今同じ時間に読んでいる人数が見える。他に読んでいる人のつぶやきも見え、いいねできる。同じ本を読んでいる人が見える。読書時間を記録する。
4. **プロフィール** — フォロー、フォロワー、投稿、プロフィールと書店の編集、本をバーコードで登録、読みたい本。

右上にお知らせ。

## 追加の指示（同日・試作を見たあと）

ユーザーの指示（要約）:

- 読書を開始では、本を選ばなくてもいい。
- 読書中のつぶやきは、同じ本の人だけでなく、みんなのつぶやきが見えてほしい。
- タイムラインではネタバレを隠すが、「表示する」ボタンを押したら見られるようにする。
- ホームの「本棚」は「書店」に変更する。
- そのため「街を歩く」「一冊からたどる」「書店一覧」はいらない。
- 書店一つひとつの表示が長いので、もう少し小さくしてよい。大きく見たいなら、その書店のページに飛んでもらう。
- プロフィールの挨拶の下に、noteやYouTube、公式サイトなどのURLを貼れるようにする。

反映した内容:

- **読書の開始**: 本は任意。本なしで始めた読書では、「読み終えた！」とネタバレの印は出さない。読書時間は記録する。
- **読書中のつぶやき**: 読書の画面（開始前・読書中とも）に「みんなの読書中のつぶやき」を表示する。本に関わらず、「みんなで読む」の投稿と、自分だけのメモが並ぶ。「同じ本を読んでいる人」の一覧は残す。
- **ネタバレ**: タイムラインとプロフィールでは本文を隠して並べ、「表示する」で読める。作品ページの扉、お知らせから除外する扱いは変えない。
- **ホーム**: タブは「書店｜タイムライン」。「街を歩く」「一冊からたどる」「書店一覧」を外した。本は「検索」から探す。（2026-10-14 の作り直しで、タブは「ホーム｜便りだけ」になった。下の「実装状況」を参照）
- **書店カード**: 店名・店主・フォローを1行にまとめ、最初の公開棚を1段だけ小さく表示する。ほかの棚は「この書店へ」から書店のページで見る。
  - 小さくしたことで、スマホでも棚が1画面に収まり、横スクロールしない書店がある。「横＝棚」の操作は、書店のページの大きな棚と、本を手に取った画面で続く。
- **プロフィールのリンク**: 自己紹介の下に最大5件。
  - note・YouTube・X・Instagramなどはサービス名、それ以外はサイト名（ドメイン）で表示する。
  - http/httpsのみ受け付ける。別タブで開き、リンク先には参照元を渡さない。
  - デモの読書家にはリンクを付けていない（実在のページに見えないように）。

## 追加の指示（2026-10-11・プレビューへのコメントと依頼）

ユーザーの指示（要約）:

- ホームの書店タブのジャンル絞り込みはいらない。
- 本の画面に定価が必要。「この店主が選んだ、ほかの一冊」にも定価を。
- 購入は、わざわざクリックしなくてもAmazonや楽天に飛べるように。もう少し縦に短く。
- 作品ページのレビューは3件載せて、残りは「すべて表示」ボタンで。
- 読書を始めるときに「はじめますか？」の確認がほしい。「コーヒーのご用意はできましたか？」のような言葉がランダムに出ると可愛い。
- 読書をやめるときも確認がほしい（「しおりはちゃんと挟めましたか？」など）。
- つぶやきにタグを付けられるように。
- 各ユーザーにIDが必要。

反映した内容:

- **ジャンル絞り込み**: 書店タブから外した。ジャンルは「検索」で選べる。「フォロー中」の絞り込みは残す。
- **定価**: 本を手に取った画面、作品ページ、「ほかの一冊」に税込の定価を出す。
  - デモの本の定価は仮の値で、購入欄に「定価はデモ用の仮の値です」と書く。
  - 登録した本は、openBDから取れた価格（本体価格に税10%を足した値）か、手入力の値を使う。
- **購入リンク**: 「購入する」の横にAmazon・楽天ブックスのボタンを常に表示する。注記は1行にした。
- **レビュー**: 新しい順に3件。残りは「残りのレビューをすべて表示（N件）」で開く。
- **読書の開始・終了の確認**
  - 開始時は「読書をはじめますか？」と、読み方と本を確認する。言葉はランダムに選ぶ（「コーヒーのご用意はできましたか？」「スマホの通知は、少しお休みにしますか？」など）。
  - 終了時は「読書を終えますか？」と今回の読書時間を出す（「しおりは、ちゃんと挟めましたか？」など）。
  - 「読み終えた！」のときは「読み終えましたか？」と聞く（「最後のページまで、おつかれさまでした。」など）。
  - どちらも、やめる（「もう少し準備する」「もう少し読む」）を選べる。
- **タグ**
  - 本文に「#ことば」と書くとタグになる（前に空白か行頭が必要）。投稿ではタグがリンクになり、押すと同じタグの投稿を検索で一覧できる。
  - 投稿欄の下に、付けたタグと、よく使われているタグの候補を出す。
  - 検索の最初の画面に「よく使われているタグ」を出す。自分だけのメモのタグは、どこにも出さない。
  - よく使われているタグ（検索の最初の画面と投稿欄の候補）は、そのまま読める投稿からだけ集める。ネタバレ（印があるもの、たたんでいるもの、設定で出さないもの）と、通報でたたんでいる投稿のタグは出さない（タグそのものがネタバレや個人情報のことがあるため）。出したタグは、押せば必ず読める投稿につながる。設定でネタバレを出さない人がタグで探したときは「ネタバレを含むかもしれない投稿は、設定により出していません」と1行だけ出す（件数は出さない）。
- **ユーザーID**
  - 全員に「@id」を付けた。デモの読書家は @nagi・@sumire など。自分の初期値は @reader。
  - IDは投稿・プロフィール・フォロー一覧に出す。プロフィールの編集で変えられる（3〜20文字の半角英小文字・数字・_、ほかの人と重複不可）。
  - 検索では @ID・名前で読書家を探せる。

## 追加の指示（2026-10-11・プレビューへのコメント 2）

- **購入ボタンの位置**: 「購入ボタンはここに置いて」（本を手に取った画面のタイトル・定価の部分）。→ 定価のすぐ下に「Amazon」「楽天ブックス」のボタンを置いた。作品ページも同じ並びにした。注記（定価は仮の値、外部書店で検索することなど）は画面下の小さな説明にまとめた。
- **ほかの書店のカード**: 「押したら書店に飛べるように」（「この店のPOPを読む」ボタン）。→ 「この書店へ」に変え、その書店のページの該当する棚へ移る。ボタンは書店名のすぐ横に置いた。その書店のPOPは、カードの棚で本をタップすれば、これまでどおりその場で読める。
- **表紙**: 「表紙をタップで作品ページに飛べるように」。→ 本を手に取った画面の表紙を、作品ページへのリンクにした。
- **本棚の編集**: 「本を連続で選択できるように」「本を並べるではなく、本棚を編集にして」「すでに並んでる本をタップしたら本棚から削除できるように」。
  - ボタン名と画面名を「本棚を編集」にした。棚が満席でも開ける。
  - 本を選んでも画面を閉じず、続けて何冊でも選べる。押すたびに「並べる／外す」が切り替わる。
  - もともと棚にあった本（POPを書いた本も）も、押せば外せる。外した本は「外しました・押すと戻す」と表示され、もう一度押すとPOP・並べ方・元の位置ごと戻る。
  - 下に「この画面で○冊並べました・○冊外しました」を出し、「完了」で閉じる。
- **書店カードの棚**: 「棚は2つ表示」。→ ホームの書店カードに公開棚を2段まで表示する（3段目以降は書店のページで）。
- **読書を終える確認**: 「（終えるボタンは）本を閉じる」「感想を書くボタンも欲しい」。→ ボタンを「もう少し読む」「感想を書く」「本を閉じる」にした（読み終えたときは「読み終えた」）。「感想を書く」は読書を記録して終え、その本の感想を書く画面を開く。

## 確認したこと・決定

- **ホームの切り替え（決定）**: 本棚の上のスワイプと、ホーム自体のスワイプの判定を分ける。
  - 理由: 「横＝棚」は第1回会議で強く支持された操作で、ホームの左右スワイプとぶつかるため。
- **読書中であることの見せ方（決定）**: 読書を始めるときに「一人で読む」「みんなで読む」を選ぶ。
  - 既存原則「読書状況を勝手に公開しない」との関係: 本人が選んだときだけ見える。
- **範囲（決定）**: 全部まとめて試作する。

## 実装状況（試作）

このブラウザだけに保存する試作。他の利用者がいないため、「いま読んでいる人」はデモの読書家で再現している。

- **実装済み**
  - **下のバーとお知らせ**: 下のバー4項目。PC幅では左のサイドバーに同じ4項目。右上のベルでお知らせ（未読数つき）。
  - **ホーム（2026-10-14 から）**: 上部に「ホーム｜便りだけ」のタブ（当初は「本棚」、のちに「書店｜タイムライン」）。切り替えはアドレス（`/` と `/timeline/`）を置き換えるだけで、「戻る」の段を増やさない。左右スワイプでも切り替わる。
    - 棚・カルーセル・特集のレール・横にスクロールする要素・画面の左右の端・本を開いた画面の上でのスワイプは、切り替えに使わない。
    - 「ホーム」は上から「今日の街」、四つの入口、読んでいる本の一行、特集と掲示板を挟んだ便り、路地（もとの書店タブの店先。公開の棚を2段まで、本物の棚のまま）。「便りだけ」はフォローした人と自分の便りだけ。決まりは [09](./09_段階2_ログインと保存.md) の「ホーム：「ホーム」と「便りだけ」」と、共有フォルダの「ホームの作り直し_開発計画_2026-10-14.md」の PR 1b。
  - **投稿ボタン**: 右下の丸いボタン。アイコンはプロフィールの「設定」で万年筆・タイプライター・羽根ペンから選ぶ。
  - **投稿のカード（便り、2026-10-14 から）**: 投稿は、タイムライン、本のページの感想（扉の向こうも）、プロフィール、タグの検索、読書中の「みんなの読書中のつぶやき」と「今回書いたこと」の7か所で、同じ「便り」のカードで出す（ホームの試作 v37 の形。平らな枠と顔の列、名前・@ID・店主・時刻、15px の本文と長い便りのたたみ、本の行と［読みたい］、返信・いいね・「…」）。返信はカードの下では開かず、右から重なる便りのページ（`/post/?id=`）で読み、書く。返信の数、いいねの数、読みたくなった人の数は出さない。決まりは [09](./09_段階2_ログインと保存.md) の「書く画面」「ネタバレの表示」と、共有フォルダの「ホームの作り直し_開発計画_2026-10-14.md」の PR 1a。
  - **本の検索**: 投稿・返信・読書開始の本選びは、タイトル・著者・ジャンル・ISBNで検索して選ぶ。
  - **検索画面**: 本と書店を探せる。何も入力していないときは、次の3つを並べる。
    - 「話題の本」: 投稿数の多い本
    - 「人気の本」: 公開棚の数と「読みたくなった」の数で並べた本
    - 「棚の隅の本」: 公開棚が1つ以下で、レビューのない本
  - **読書を開始**
    - 初期選択は読んでいる途中の本（最後に読んだ、まだ読み終えていない本）。
    - 「一人で読む」「みんなで読む」を選んで開始する。タイマーで読書時間を記録し、「読書を終える」「読み終えた！」で終える。
    - 読書中のつぶやき: 一人で読むときは自分だけのメモ。みんなで読むときは公開の投稿で、「読書中のつぶやき」の印が付き、タイムラインと作品ページにも出る。
    - いま「みんなで読む」にしている人数と一覧、同じ本を読んでいる人、その本の読書中のつぶやきが見える。いいねもできる。
  - **プロフィール**: 投稿数・フォロー・フォロワー・読書時間。プロフィール編集、書店を編集、本を登録、設定。読みたい・お気に入り・登録した本の一覧。
  - **本の登録**
    - カメラでのバーコード読み取り（BarcodeDetector対応ブラウザのみ）か、ISBNの入力。
    - ISBNはチェックディジットまで検証する。書籍情報はopenBDから取得を試み、取れないときは手で入力する。
    - 表紙はオリジナルの仮デザインで描き、実際の表紙画像は使わない。
  - **お知らせ**: 次の4種類から作る。架空の通知で水増ししない。
    - 自分の投稿への返信
    - フォロー中の人の投稿
    - 読みたい本への感想
    - 同じ本をみんなで読んでいる人
- **試作で仮に決めたこと（要確認）**
  - フォローは、これまでどおり「その人の書店をフォローする」と同じ扱い。人と書店を分けるかは未決定。
  - フォロワーは、デモの読書家は書店のフォロー数を表示する。自分は0（他の利用者がいないため）。
  - みんなで読むときのつぶやきは、タイムラインと作品ページのレビューにも並ぶ。読書中の途中経過がレビューに混ざってよいかは要確認。
  - 「人気」「話題」の数え方は暫定。
  - 書籍データソースにopenBDを試しに使っている。正式な書籍データソースと、作品と版の識別は未決定（[04](./04_未決定事項と次回議題.md) の「実サービスの基盤」）。
- **未実装・できないこと**
  - 本当の意味でのリアルタイム（他の利用者との共有）。ログイン・共有DBが必要。
  - お知らせのプッシュ通知、読了時に感想を書いた人へ伝える流れ。
  - 読書ページ数・進捗の記録、読書の目標。
