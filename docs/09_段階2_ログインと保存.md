# 段階2：ログインと保存

> 更新日: 2026-10-12 / 状態: その3（保存先の切り替え）を実装

今はデータがブラウザの中（localStorage）にしかなく、ログインも本物のユーザーもいません。段階2では、Supabase にデータベースとログインを置き、最初の店主たちが本当に本屋を開けるようにします。技術構成はユーザーから Claude に一任されています（2026-10-12）。

## 決めたこと

- **保存先は Supabase**（Postgres、ログイン、画像の保存）。
- **段階2では静的な書き出し（`output: "export"`）を続け、ブラウザから Supabase を直接呼ぶ。** 誰が何を読めて書けるかは、すべてデータベースの行レベルセキュリティ（RLS）で決める。アプリ側の判定だけには頼らない。
  - 理由: スマホアプリ化（Capacitor）と相性がよく、自前のサーバーなしで安全に作れる。本屋ごとの紹介画像（OGP）のためのサーバー処理は段階4で足す。
- **ログインは、メールに届く6桁のコードか、メールのリンク。** パスワードはない。コードはWebでもスマホアプリでも同じ手順で使え、リンクは同じ端末のブラウザで開くときに便利。
  - 最初の20人は招待制なので、Supabase の新規登録を止め、店主のメールアドレスをダッシュボードの Authentication → Users → Add user で先に登録しておく。
  - メールの件名と本文は `supabase/templates/magic_link.html`（コードとリンクの両方）。Supabase は独自のメール送信（SMTP）を設定するまでメールの文面を変えさせず、標準の英語のメールにはリンクしか入らない。それまではリンクでログインする。コードの有効期限は10分。
  - リンクの戻り先はログイン画面（`/login/`）。Supabase の Authentication → URL Configuration で、Site URL を本番のURLにし、Redirect URLs に本番と、試したいPRのブランチのURL（末尾に `/**`）を入れる。リストにない戻り先は Site URL に置き換わるので、ほかのサイトにログインの鍵が渡ることはない（`pnpm test:supabase` で確認）。
  - プレビューのURLは `*-booktown1.vercel.app` のようなワイルドカードで許可しない。`*` はハイフンをまたぐので、名前が `booktown1` で終わる他人の Vercel チームのURLにも当てはまってしまう。ブランチごとの決まったURL（`book-town-851k-git-<ブランチ名>-booktown1.vercel.app`）を1つずつ足す。
  - Google と Apple のログインは、ストアの審査条件に合わせてアプリ公開前に足す。
- **公開先は Vercel**（プロジェクト `book-town-851k`、本番は https://book-town-851k.vercel.app/ ）。main への取り込みで本番が更新され、PRごとに確認用のURLができる。ビルド時に `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`（または旧名の `NEXT_PUBLIC_SUPABASE_ANON_KEY`）を渡す。どちらも公開してよい値で、なければデモのまま動く。Vercel では種類を「Config」にして、Production、Preview、Development のすべてに入れる（「Secret」で保存すると書き込み専用になり、あとから種類を変えられないので、消して作り直す）。収益を得る段階では Vercel の有料プランが必要になる。
- **1人1店舗**（`shops.owner_id` に一意制約）。複数店舗にするときはこの制約を外す。
- **数を見せない。** フォロワー数や反応の数は、他の人が数えられないようにしてある（思想メモ「数で価値を決めない」）。反応を見られるのは、反応した人と受け取った人だけ。画面でも、本屋のフォロワー数は店主本人にだけ「この数はあなたにだけ見えています」と添えて出す。デモの書店とデモの読書家は、今までどおり数を出す。

## 表と公開範囲

| 表                                | 中身                                     | ログインなしで読める | 他の人が読める           | 書けるのは                               |
| --------------------------------- | ---------------------------------------- | -------------------- | ------------------------ | ---------------------------------------- |
| `profiles`                        | プロフィール（ID、名前、紹介、リンク）   | ○                    | ○                        | 本人                                     |
| `books`                           | 本（国立国会図書館の目録、または手入力） | ○                    | ○                        | 手入力は入力した本人。目録はサーバーのみ |
| `profile_nine`                    | 人生の9冊                                | ○                    | ○                        | 本人                                     |
| `shops`                           | 本屋の基本情報と、公開している棚・店内   | 開店中のみ           | 開店中のみ               | 店主                                     |
| `shop_private`                    | 非公開の棚を含む、本屋の全データ         | ×                    | ×                        | 店主                                     |
| `shop_follows`, `profile_follows` | 本屋のフォローと人のフォロー（別々）     | ×                    | フォローした人とされた側 | 本人                                     |
| `shop_reactions`                  | 本屋へのいいね、店主へのひとこと         | ×                    | 反応した人と店主         | 本人                                     |
| `saved_shops`                     | あとで行く本屋                           | ×                    | ×                        | 本人                                     |
| `pop_reactions`                   | POPへの反応                              | ×                    | 反応した人と店主         | 本人                                     |
| `posts`                           | 投稿、レビュー、読書メモ                 | ひとりメモ以外       | ひとりメモ以外           | 本人（削除のみ、編集はなし）             |
| `post_reactions`                  | いいね、読みたくなった                   | ×                    | 反応した人と投稿者       | 本人                                     |
| `spoiler_reports`                 | ネタバレの報告                           | ×                    | 報告した人のみ           | 本人                                     |
| `book_marks`                      | 読みたい、お気に入り、持っている、読了   | ×                    | ×                        | 本人                                     |
| `reading_sessions`                | 読書の記録                               | 「一緒に読む」のみ   | 「一緒に読む」のみ       | 本人                                     |
| `blocks`                          | ブロック                                 | ×                    | ブロックした人のみ       | 本人                                     |
| `reports`                         | 通報（投稿、本屋、プロフィール）         | ×                    | 通報した人のみ           | 本人（状態の変更は運営のみ）             |

- **非公開の棚**: 店主のアプリは全部の棚を `shop_private` にだけ書く。公開する棚は、データベースのトリガーが `shops.public_shelves` に写す。店主は `public_shelves` と `public_scene` を自分では書けない（列ごとの権限）。アプリに不具合があっても、非公開の棚が他の人に届くことはない。
- **他の人の本屋のデータ**は、読み込むときに必ず検証する。棚は `cleanShelves`（`src/lib/town-remote.ts`）で、形が崩れた棚や知らない本を落とす。店内（Scene）は、データベースに移すときに `validateScene` で同じようにする。
- **ブロックは双方向に効く。** どちらからも相手の本屋、投稿、一緒に読む記録が見えなくなり、フォローは両方向とも外れ、新しいフォローや反応、返信もできない。プロフィールだけは見えるままにして、ブロックした人が自分の一覧から解除できるようにしている。誰が誰をブロックしたかは、本人以外には調べられない。
- **通報**は運営が Supabase のダッシュボードで読み、状態を変える。アプリストアの審査でも、ブロックと通報は投稿のあるアプリに求められる。
- **返信は1段まで**、ひとりメモには返信できない。どちらもデータベースのトリガーで止める。
- **退会**すると、その人のデータはすべて消える。手入力した本だけは目録に残り、作成者が空になる。

## その3で決めたこと（保存先の切り替え）

- **画面は今までの `TownState` のまま使う。** ログインしている人の街はデータベースから組み立て、自分は `me`、自分の本屋は `mine` という今までの呼び名に置き換える（`townFromRows`）。画面の部品はデモと同じものが動く。
- **保存は差分で、後ろで行う。** 最後にデータベースが受け取った街と今の街を比べ、変わった行だけを書く（`planWrites`）。どの書き込みも、やり直しても同じ結果になる。0.4秒待ってまとめて送る。
  - つながらないときは 2秒、5秒、15秒、30秒と間を空けて送り直し、画面の上に「つながらないため、まだ保存できていません」と出す。保存前の変更があるままページを閉じようとすると、ブラウザが確認する。
  - データベースが断った変更（ほかの人が先に取ったIDなど）は、読み込み直して画面を本当の状態に戻し、「保存できない変更があったため、保存されている状態に戻しました」と出す。
  - アカウントを読み込めないときは、空の街に「読み込み直してください」と出し、何も保存しない。
- **新しい本屋は、作った時点で開店している**（デモと同じ）。閉店の切り替えは、本屋の公開ページ（段階4）で足す。
- **投稿の時刻はデータベースが決める。** 端末の時計に関係なく、未来や過去の日付で投稿して上に居座ることはできない。
- **人生の9冊は、関数 `replace_profile_nine` でまとめて置き換える。** 並べ替えの途中で一意制約に当たらず、失敗しても前の9冊が残る。
- **IDの付け方。** 投稿、読書、本はデータベースと同じ UUID。棚と棚の中の本は本屋のデータの中だけで使うので、今までどおりの連番。
- **データベースの本屋と読書家のページは `/shop/?id=…` と `/profile/?id=…`。** 静的な書き出しでは、ビルドの時点で知っているデモの本屋しかページを作れないため。デモの本屋は今までどおり `/shops/…/`。
- **読み込む量の上限。** 各表1000行、投稿は新しい順に500件、本は新しい300冊と、街に出てくる本。人数が増えたら、街を歩く範囲ごとに読む形に変える。
- **お知らせの既読は、その端末にだけ覚える**（localStorage、アカウントごと）。
- **まだブラウザに残るもの（その3b）。** 店内の飾り付け（Scene）、本屋へのいいねとひとこと、あとで行く本屋、本屋めぐりの記録は、まだこのブラウザの中だけに保存する。画面の文言もそのまま「送信されないデモ」と出している。

## 検証

- `pnpm test:db`: PGlite（Node.jsで動くPostgres）にマイグレーションを流し、ログインなし・本人・他人の立場で、読める・書ける・拒否されることを確かめる。
- `pnpm test:supabase`: 手元で `supabase start` した本物の Supabase（ログイン、コードのメール、REST、RLS）に対して、招待、コードでのログイン、最初のプロフィール作成、ログアウトを通す。続けて2人の読書家が街を使い、保存したものが読み込み直しても残ること、公開したものだけが相手に届くこと、断られた変更が画面で戻ること、つながらないあいだの変更があとで保存されることを確かめる。`supabase status -o env` の値を環境変数に入れてから実行する。
- `pnpm test:town-sync`: データベースなしで、行から街を組み立てる処理と、書き込みの計画を確かめる。
- GitHub Actions の CI（`.github/workflows/ci.yml`）で、PRごとに型チェック、lint、ドメインテスト、データベーステスト、ビルド、ブラウザでのログイン、本物の Supabase でのログインを回す。
- `supabase/config.toml` の `[auth.email] enable_signup` はメールでのログインそのもののスイッチなので、`true` のままにする。新規登録を止めるのは `[auth] enable_signup = false` のほう。

## データベースへの反映

- `supabase/migrations/` のファイルが `main` に入ると、GitHub Actions の Deploy database（`.github/workflows/deploy-database.yml`）が Supabase に適用する。
- 必要なリポジトリシークレットは `SUPABASE_ACCESS_TOKEN`、`SUPABASE_DB_PASSWORD`、`SUPABASE_PROJECT_ID`。未設定のあいだは警告を出して何もしない。設定後に Actions の画面から手動で再実行できる。
- 一度適用したマイグレーションは書き換えない。変更は新しいファイルで足す。新しい表には必ず RLS と権限を書き、`tests/database-policies.test.ts` に確認を足す。

## 本番の設定（ログインのメールと Vercel）

- 本番の Supabase のログイン設定は `supabase/hosted-auth.json` と `supabase/templates/magic_link.html` に書く。`main` に入ると Supabase auth settings（`.github/workflows/supabase-auth.yml`）が本番をそれに合わせ、PR では何が変わるかだけを確かめる。Actions の画面から check（確かめるだけ）と apply（合わせる）を手動でも動かせる。
- 合わせるのは、ログインコードの桁数と有効期限（6桁・10分。手元の `supabase/config.toml` と同じで、`pnpm test:settings` が食い違いを止める）と、`RESEND_API_KEY` があるときのメール送信（Resend の SMTP、送信元、1時間あたり30通、メールの件名と本文）。Supabase 標準のメールのままでは、文面も上限も変えられない。サイトのURLと戻り先のURL（Authentication → URL Configuration）は、画面で設定したまま触らず、ログに表示だけする。
- 必要なリポジトリシークレットは `SUPABASE_ACCESS_TOKEN`（booktown だけを対象に、Project Settings と Auth Config を Read-write、API Keys と API Key Secrets を Read）、`SUPABASE_PROJECT_ID`、`RESEND_API_KEY`（Resend の Sending access の鍵）。
- ドメインを用意するまでは、送信元は `onboarding@resend.dev` で、Resend のアカウントのメールアドレスにしか届かない。最初の20人を招待する前に、ドメインを Resend で確認し、`hosted-auth.json` の `sender` をそのドメインのアドレスに変える。
- Vercel は `VERCEL_TOKEN`（booktown1 チームの全プロジェクト）を使い、Vercel（`.github/workflows/vercel.yml`）から操作する。status でブランチの最近のデプロイと、失敗したビルドのログの末尾を見る。deploy でブランチをもう一度ビルドする（`main` は本番）。プレビューがビルド前に数秒で止まったときは deploy でやり直す。
- リポジトリは公開なので、Actions のログも誰でも読める。スクリプトは決めた設定の値だけを表示し、鍵、パスワード、メールの本文は表示しない。認証のログ（メールアドレスが入る）もここには出さない。

## 段階2の進め方

1. **その1: データベースの土台。** この文書、マイグレーション、テスト、CI、反映の仕組み。
2. **その2: ログイン画面と、最初のプロフィール作成**（IDと名前）。Supabase の設定がない環境では、今のデモのまま動く。
3. **その3: 保存先の切り替え。** 自分のプロフィール、本屋、投稿、読書の保存先をブラウザから Supabase に移し、他の人の本屋と投稿をデータベースから読む。入力の上限をデータベースに合わせる（本屋の名前80文字、紹介2000文字、POP 1000文字など、`src/lib/types.ts`）。
   - **その3b:** 店内の飾り付け、本屋へのいいねとひとこと（上限2000文字）、あとで行く本屋、本屋めぐりの記録もデータベースへ移す。
4. **その4: 引き継ぎ。** このブラウザに保存してあるデータを、初回ログイン時にアカウントへ移せるようにする。

## まだ決めていないこと

- **メールの送信元のドメイン。** ログインのメールは Resend 経由で送る（「本番の設定」）。ドメインを用意するまでは Resend のアカウントのアドレスにしか届かないので、最初の20人を招待する前にドメインを決めて Resend で確認するか、Google ログインを先に入れる。

- 読書記録の公開範囲（登録時に「公開／自分だけ」を選び、あとから1冊ずつ隠せる案をユーザーに確認中）。今の `book_marks` はすべて本人だけが見られる。公開できるようにするときは、列を足すマイグレーションで対応する。
- 利用できる年齢（13歳以上の案を確認中）。登録画面での確認は、その2で入れる。

- 本のデータの取得元。国立国会図書館を土台にする案をユーザーに確認中。`books.source = 'ndl'` の行は、段階3でサーバー側の関数から入れる。
- 連投やスパムの制限。最初の20人のあいだは様子を見る。
